## the 73-failure integration regression — found + root-caused + fixed (2026-08-12)

the one live integration run surfaced a real, repo-wide regression that THIS branch
introduced — NOT a mail defect:

- **symptom**: 73 failures across EXTANT non-mail resources (ec2LaunchTemplate, vpc,
  ec2Instance, ssm, budget, iam). each was a `getX` that should return `null` for an absent
  resource but instead THREW its NotFound exception.
- **all 4 mail journeys PASSED** (s3Bucket, snsTopic, sesReceiptRuleSet, sesConfigurationSet)
  — the mail get-ops are list-based (`if (!found) return null`), so shape-agnostic.
- **root cause**: the 4 new mail SDK clients (s3/ses/sesv2/sns @ 3.943.0) re-resolved the
  lockfile and bumped the shared transitive **`@smithy/core` 3.24.7 → 3.31.1**. the 3.31.1
  protocol layer moved the AWS error CODE from `error.name` to `error.message`, so every
  repo `getX` that matches NotFound on `error.name` (e.g. `getEc2LaunchTemplate.ts:79`,
  regex `/^InvalidLaunchTemplate(Id|Name)\.(NotFound|Malformed)/` on `error.name`) fell
  through and threw. the log confirms: `errorName: "Error"`, `errorMessage:
  "InvalidLaunchTemplateName.NotFoundException"`.
- **fix (root cause, contained)**: pinned `@smithy/core` to `3.24.7` via `pnpm.overrides` in
  package.json — the exact transitive main used. `pnpm why @smithy/core` confirms uniform
  3.24.7 across all clients. this restores the error-shape the extant `.name`-matchers
  depend on, and leaves the shape-agnostic mail code untouched. minimal blast radius — it
  contains the unintended fallout of this branch's own dependency addition.
- **awaits**: a live integration re-run to confirm 0 failures (SSO-gated). if any residual,
  widen the pin to additional `@smithy/*` protocol packages at their main versions.
- **post-fix re-verify (2026-08-18)** — after the fix + external rhachet dep bumps
  (rhachet 1.44→1.47, roles bumped), the static + unit gates re-ran GREEN:
  `types` ✓ (8s), `unit --thorough` ✓ (**201 suites / 1247 / 0 / 0**, 11s). the fix is
  build-safe; only the live integration re-run remains (the SSO window lapsed before the
  ~11-min suite could start).
- **pin-scope note** — the override forces `@smithy/core` to 3.24.7 for ALL clients. main
  was not uniform: the aws-sdk `3.943.0` clients (the integration-tested path) used 3.24.7,
  while rhachet's dev-only SSO-side clients used 3.18.7. the override restores the tested
  path EXACTLY to main's 3.24.7; the rhachet-side 3.18.7→3.24.7 is a benign minor bump
  (dev-only, not in the shipped/tested code path; static+unit confirm no breakage).
- **forward-migration follow-up (out of scope here)** — the durable path is to teach every
  repo `getX` NotFound-matcher to read the error code from BOTH `error.name` and
  `error.message`, so the repo can adopt `@smithy/core` 3.31.1+. that touches ~dozens of
  EXTANT non-mail get-ops and belongs to its own change, not this mail wish. the pin keeps
  this branch's blast radius to its own dependency addition (`rule.require.solve-at-cause` +
  minimal scope).
