## upfront decisions

- **net-new AWS SDK deps** (repo has none of these today — verified against `package.json`):
  - `@aws-sdk/client-s3` — bucket + bucket policy + lifecycle
  - `@aws-sdk/client-sns` — the event sink topic
  - **v1 `@aws-sdk/client-ses`** — ONE client covers the whole SES surface: identity
    (`VerifyDomainIdentity`/`VerifyDomainDkim`/`GetIdentityVerificationAttributes`/
    `GetIdentityDkimAttributes`), mail-from (`SetIdentityMailFromDomain`), config-set +
    event-destination (`CreateConfigurationSet`/`CreateConfigurationSetEventDestination`),
    receipt rules (`CreateReceiptRuleSet`/`CreateReceiptRule`/`SetActiveReceiptRuleSet`),
    and send (`SendRawEmail`). receipt rules live ONLY in v1, so v1 is required anyway.
- **decision — SES v1 + v2 split (REVISES the earlier "v1 only"; the vision already sanctioned
  "we live in both")**: v1 SES cannot tag identities or config-sets, and the vision's input
  tables list `tags` as consumer-set on `DeclaredAwsSesEmailIdentity` + `DeclaredAwsSesConfigurationSet`.
  so:
    - **v2 `@aws-sdk/client-sesv2`** — `DeclaredAwsSesEmailIdentity` (CreateEmailIdentity handles
      domain|email + dkim + tags in one call; PutEmailIdentityMailFromAttributes for mail-from;
      GetEmailIdentity reads dkim tokens + verification status), `DeclaredAwsSesConfigurationSet`,
      `DeclaredAwsSesConfigurationSetEventDestination` (tags + modern api).
    - **v1 `@aws-sdk/client-ses`** — `DeclaredAwsSesReceiptRuleSet` + `DeclaredAwsSesReceiptRule`
      (receipt rules are ABSENT from v2). also `SendRawEmail` if a send op is ever added.
  the pivot is CLEAN — no SES resource was built when it was made. **4 net-new deps total:
  `@aws-sdk/client-s3`, `@aws-sdk/client-sns`, `@aws-sdk/client-ses` (v1), `@aws-sdk/client-sesv2`**
  at 3.943.0. FULCRUM flagged for end-of-road wisher review: the v1+v2 split (vs a v1-only trim
  that would drop identity/config-set tags).
