# case=1 — a roles anywhere grove hops into demo

feel: happy (after) · sharp (before) · care: critipath

## .narrative

a clone runs on the hetzner grove. no imds there: the box signs in through iam roles anywhere with its x509 cert. that session carries a source identity (the cert's subject cn) and principal tags.

before the fix, the clone's first demo call assumes `ehmpathy-demo-for-grove`. sts refuses: `AccessDenied ... sts:SetSourceIdentity`. the source identity persists across a role chain, so the target trust must allow it. once allowed, sts refuses on `sts:TagSession` next. the clone stalls; the reach readme's four causes do not name this one.

after the fix, the trust statement allows all three actions for the same one principal. the hop succeeds. the demo session carries the grove's source identity, so cloudtrail in demo names which cert drove each act.

## .bdd sketch

```
given('[case1] a roles anywhere session on the hetzner grove, as the camp grove role')
  when('[t0] it assumes ehmpathy-demo-for-grove while trust allows sts:AssumeRole alone')
    then('sts denies: AccessDenied on sts:SetSourceIdentity')
  when('[t1] it assumes ehmpathy-demo-for-grove while trust allows AssumeRole + TagSession + SetSourceIdentity')
    then('sts returns demo credentials')
    then('get-caller-identity shows assumed-role/ehmpathy-demo-for-grove/<session>')
    then('the demo session carries the grove source identity')
```
