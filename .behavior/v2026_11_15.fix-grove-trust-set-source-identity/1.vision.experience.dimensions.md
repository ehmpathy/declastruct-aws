# experience dimensions — -for-grove trust admits roles anywhere sessions

## .the dimensions

| # | dimension | positions |
|---|---|---|
| D1 | actor | `hopper` (a clone on a grove box, hops into demo) · `applier` (the commander: plan, read, apply) · `cicd` (github actions, `ehmpathy-demo-oidc`) |
| D2 | session origin of the hopper | `roles-anywhere` (hetzner grove; carries source identity + session tags) · `ec2-imds` (ec2 grove; carries neither) · `foreign` (any principal other than the camp grove role) |
| D3 | target trust state | `before` (`sts:AssumeRole` alone) · `after` (`sts:AssumeRole` + `sts:TagSession` + `sts:SetSourceIdentity`) · `revoked` (per `howto.revoke-grove-reach`) |
| D4 | target role (fixes the account too) | `test-role` (`ehmpathy-demo-for-grove`, demo account, declared here) · `prep-role` (a prep `-for-grove` role; declared in no ehmpathy repo) · `next-role` (any later `ehmpathy-*-for-*` role, declared with a trust copied from an old example) |
| D5 | applier phase | `plan` · `apply` · `re-plan` |
| D6 | hop time vs apply | `settled` · `seconds after` (iam is eventually consistent) |
| D7 | target role existence | `present` · `absent` (deleted by hand) |
| D8 | commander's go | `given` · `not given` |
| D9 | caller-side grant (the camp grove role's own permissions toward our arn) | `granted` (both actions; issue #129 says applied) · `absent` |

| D10 | plan path, at D5=plan | `runbook` (admin creds, `.env`, `npx declastruct plan`; the file apply reads) · `skill` (`rhx aws.auth.demo.plan`: keyrack test creds, read-only, its own file) |
| D11 | reach pair source, at D5=plan | `.env` · `shell` · `live role` (read off `ehmpathy-demo-for-grove`; principal unchecked) · `half` (one var of two) · `malformed` (set but not an id or role name: blank, padded, quoted, an arn) |

D4 merges account and role: each role lives in exactly one account, so a separate account axis would only correlate with it.

## .the sub-spaces — why the axes split

D1 is not orthogonal to the rest: each other axis varies for one actor only. so the product splits into one sub-space per actor. within each, the axes are orthogonal:

| sub-space | axes | why orthogonal within |
|---|---|---|
| hopper | D2 × D3 × D4 × D6 × D9 | origin is set by the box; target trust by our last apply; target role by the hop's arn; hop time by the clock; caller grant by the collaborator's last apply. no one of them sets another |
| applier | D5 × D7 × D8, at D4=test-role | phase is the commander's step; existence is set by prior applies or a hand delete; the go is his word |
| cicd | D3 | cicd reads another role; only "did this change touch it" varies |

two in-sub-space correlations, stated rather than hidden:
- D7=absent is only observable at D5=plan: it STOPs there, so apply and re-plan never meet it
- D8=not given only bites at D5=apply: plan and re-plan need no go
