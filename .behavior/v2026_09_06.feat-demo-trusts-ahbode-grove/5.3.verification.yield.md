### 🔴 a second defect, found at the frictionless review and FIXED here

**the absent-`.env` throw gates EVERY apply of this provision** — the oidc CI repair among them
(`howto.reapply-demo-oidc-role` step 2). so it fires on an operator mid-outage who has no `.env` and
no route into the collaborator's private tree, and its read-back is their whole way through.

**that read-back was carried in two shapes, and the error's shape was the degraded one:**

| where | what it handed the operator |
|---|---|
| `readme.md:81-82` | `--query 'Role.…Principal.AWS'` **`--output text`** ✅ |
| the **error message** | `--query Role.…Principal.AWS` — unquoted, **no `--output text`** ⛔ |

⛔ **absent `--output text` the aws cli prints JSON**, so the read-back yields
`"arn:aws:iam::…"` **with quotes**. an operator pastes those into `.env`, they ride into the trust
principal, and 🔴 **the reach then fails at RUNTIME with an `AccessDenied` no apply can surface** —
a self-inflicted instance of the vision's **fourth** `AccessDenied` source, the one
`get-caller-identity` cannot discriminate.

⇒ **and it falsified a claim in the readme**: *"the absent-var error names this command too, so an
operator who hits the throw needs no second lookup."* it named a **variant**. that sentence is true
now, and it was the fix's target rather than a separate edit.

**fixed** — one constant (`CAMP_REACH_ENV_HINT`, whose own `.note` reads *"the hint drifts in one
place or in none"*), plus a `.note` that records why each flag carries load, so a tidy-up cannot
quietly drop either.

🔴 **the clamp had NO TEETH before, which is how this survived to the verification stone.** the
extant assert was `toContain('aws iam get-role')` — it passed on the degraded string. two asserts
added (`--output text`, and the quoted `--query`), then dogfooded:

| step | result |
|---|---|
| fix in place | ✅ `13 passed, 0 failed` |
| **fix reverted** | 🔴 **`12 passed, 1 failed`** |
| fix restored | ✅ `13 passed, 0 failed` |

⇒ **the durable lesson: the path that gates every apply is the one least likely to be walked.** it
fires only when a file is absent, so every run *with* a `.env` passes over it. **a guard that fires
rarely needs a tighter assert than one that fires always, not a looser one.**

### 🔴 a third defect, found at the ergonomics review and FIXED here

**the input contract had a pit-of-failure at its most-walked entrance.** `.env.example` ships
**placeholder values**, never empty ones — so:

```sh
cp -n provision/aws.auth/account=demo/.env.example provision/aws.auth/account=demo/.env
source provision/aws.auth/account=demo/.env      # ← both vars are now SET
```

⇒ the absent-var guard is `process.env.X ?? throw`. it fires on **absent**, and a placeholder is
**present**. 🔴 **so an operator who missed the "fill in the values" comment between those two lines
got a clean plan, a clean apply, and a reach that died at RUNTIME** with the vision's fourth
`AccessDenied` — the one `get-caller-identity` cannot discriminate.

**fixed** — two guards, each justified by its own var's invariant:

| var | the guard | why this shape |
|---|---|---|
| `GROVE_REACH_CAMP_ACCOUNT_ID` | `/^\d{12}$/` | an aws account id is exactly 12 digits |
| `GROVE_REACH_CAMP_ROLE_NAME` | equality against the placeholder constant | ⚠️ a **shape** check would pass it — `__the_camp_grove_role_name__` is a **legal** aws role name, underscores included |

🔴 **and the 12-digit check catches three slips, not one** — the unfilled placeholder, a value pasted
**with its json quotes**, and the whole **arn** pasted where the id was wanted. ⇒ the middle one is
the residue of the defect above, so **two independent nets now sit under one slip**.

**the clamp — four cases, all proven to bite.** every new case **SETS** both vars, so each sails past
the pre-existent absent-check, which is exactly why that check could never have caught them:

| step | result |
|---|---|
| guards in place | ✅ `17 passed, 0 failed` |
| **both guards disabled** | 🔴 **`13 passed, 4 failed`** — all four `NoErrorThrownError` |
| guards restored | ✅ `17 passed, 0 failed` |

⇒ `NoErrorThrownError` four times over is the whole proof in one word: with the guards gone, every
bad value passes **silently**.

🔴 **the durable lesson: a scaffold that ships PLACEHOLDERS turns an absent-check into a no-op.**
`?? throw` reads as a complete guard and covers only the empty case. **whenever a `.env.example`
ships placeholder values, the placeholder itself is an input the code must refuse** — else the
scaffold built to help the operator is what defeats the guard built to protect them.
