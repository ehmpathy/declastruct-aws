### 🔴 a third defect, found at the ergonomics review and FIXED here

## 🔴 the permadiff — root-caused, reverted, and dispatched UPSTREAM

a live `UPDATE` row surfaced on a policy nobody edited. this drive's first answer was **three
provider-level workarounds**, and the wisher struck every one:

> *"why don't you fix the permadiff upstream instead of narrow what we allow? just sort both sides"*
> — and, on the cast: *"undo this"* · *"solve it at root instead"*

### the root

`checkAreResourcesEquivalent` (in `declastruct`) compares `serialize(omitReadonly(x))`.
`serialize` defaults to `{ lossless: false, orderless: false }`, so the compare is **shape- and
order-sensitive**. iam treats a scalar and a one-element list as identical and does not promise to
echo the shape it was given. ⇒ **the plan reads `UPDATE` forever, on a document that never moved.**

🔴 **no cast can fix it, and that is structural rather than a matter of effort.** a cast holds
**one** side, so any canonicalization it performs is asymmetric by construction — it rescues a
scalar declaration and breaks a list-of-one, both legal. the desired side is built by a consumer via
`new`, which no provider library reaches. ⇒ **the compare is the one place both sides are in hand.**

### the falsification, measured

the blanket fold in the read cast ran **1302 passed / 1 failed** — the failure being
`resources.common — the bundle round-trips`, because `demoPermissionsPolicy` declares four lists of
one. ⇒ **the fold CREATED the permadiff it looked like it prevented.** that measurement is what
settles the structural argument empirically rather than by assertion.

### what landed here

| act | state |
|---|---|
| the three provider-level workarounds | ✅ **reverted.** production `src/` is **byte-identical to `origin/main`** |
| the scalar-declaration convention + its guard test | ✅ **deleted** — it existed only to keep declarations in the one shape the planner happens to handle |
| the reproduction | ✅ `castRoundTripIamPolicyStatement.test.ts` `[case6]` — **4 arms, each `toEqual(false)`** |
| the dispatch | ✅ **`ehmpathy/declastruct#71`**, QUEUED, with the patch and the falsification evidence |
| the dream | ✅ `.dream/v2026_09_18.fix.declastruct-canonicalize-before-compare.md`, symlinked into this route's `dreams/` |

**the fix, symmetric on both sides:** `serialize(canonicalize(omitReadonly(x)), { orderless: true })`
— two arms, **sort** (the flag `domain-objects` already ships) and **fold** (one-element array → bare
value, nine lines). neither changes a written document, so it can only turn `UPDATE` → `KEEP`.

### 🔴 the residual is a HUMAN's, and it is inside the issue

> **the sort arm asserts array order is never semantic in a declared resource.**

true everywhere walked in `declastruct-aws`; **unwalked** for route tables, s3 lifecycle rules, and
the stripe/unix providers. ⇒ **if any carries ordered semantics, ship the FOLD arm alone** — it
retains order and closes the reported defect on its own.

### ⚠️ `[case6]` goes RED the day the fix lands, and that red is the SIGNAL

its four arms assert the defect **as it behaves today**. when `declastruct#71` merges and this repo
bumps the dependency, they fail. ⇒ **that is the intended alarm, never a regression** — the note on
