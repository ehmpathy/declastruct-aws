# case=2 — the half-wired reach denies, and says whose half is absent

**cells** · `grove-clone × obtain × target-only`
**feel** · **sharp**  ·  **care** · **critipath**  ·  **boundary-density** · 3

> a **sharp critipath**, so it owes a fail-safe proof (`define.experience`). this is the wish's
> flagged hazard, lived through.

---

## the narrative

the provisioner applied the demo wish. the plan was green. every resource read `CREATE` or `KEEP`,
the role exists, its trust policy names the camp grove role by arn, and a reviewer who reads the diff
would sign it without hesitation.

the clone tries the assume-role and gets `AccessDenied`.

this is the trap, and it is not a subtle one: **the green apply and the broken reach are perfectly
compatible.** a reach is a pair, and this repo owns one half. the other half — an `sts:AssumeRole`
allow on the camp grove role, in `ahbode/infrastructure` — has not merged yet. the paired repo warns
about this in its own source: *"a half-wired one fails at runtime with AccessDenied, never at apply
time"* (`provision/aws.infra/account=camp/resources.reach.ts:28-31`).

so the clone gets an error that, read plainly, accuses the wrong side. aws says *"not authorized to
perform: sts:AssumeRole"* and names the **camp** principal. a clone that trusts that message will go
hunt a defect in the demo trust policy, which is correct and will stay correct however long it is
stared at.

what makes this survivable is that the fix is **findable from an artifact the clone can actually
reach**. and that qualifier is the whole design problem: the natural place to put the pointer is the
role's own `description`, which a stranded clone **cannot read** — reading it needs `iam:GetRole` in
demo, and the clone holds no demo credential at all. that is what `[t1]` just proved.

so the pointer that saves this clone is the one already on its disk: a note in
`provision/aws.auth/account=demo/`, in the checkout it is working from, readable with no aws call.
the clone greps the repo it is already in, finds the sentence, and goes to the right repo on the
first try instead of the third. the role `description` is still owed — its reader is the provisioner
or an auditor, who does have access.

## the `[tn]` timeline

```gherkin
given [case2] the target half is live   — ehmpathy-demo-for-grove exists, trust policy correct
  and  the caller half is absent        — ahbode/infrastructure has not merged the third
                                          sts:AssumeRole statement onto grove-reach
  and  a clone on an ahbode camp grove box, with the box's ambient instance role

  when [t0] the provisioner re-plans the demo auth wish
       $ npx declastruct plan --wish provision/aws.auth/account=demo/resources.ts ...
  then every resource reads KEEP
   and the plan reports no defect
   and  ^ this is the trap: our plan reads the demo account alone. the caller half lives in
        another org's account, so a green plan carries no signal about the reach at all

  when [t1] the clone assumes the demo target role
  then the call fails with AccessDenied
   and the message names the CAMP principal
       "User: arn:aws:sts::<camp-account-id>:assumed-role/<camp-grove-role-name>/... is not
        authorized to perform: sts:AssumeRole on resource: .../ehmpathy-demo-for-grove"
   and  ^ it accuses the caller, which is right, and reads as if it accuses us, which is wrong

  when [t2] the clone tries to read the role it failed to assume
       $ aws iam get-role --role-name ehmpathy-demo-for-grove
  then 🔴 IT CANNOT. the call needs iam:GetRole IN DEMO, and the clone holds no
       demo credential — that is the whole premise of [t1]
   and  ^ THE HOLE. the role's Description is a real artifact and its audience is
        a reader who ALREADY has demo access. it does not reach the stranded clone

  when [t2'] the clone reads the repo it is already checked out in
       $ cat provision/aws.auth/account=demo/readme.md
  then the note names the paired half and where it lives
       "target half of the camp-grove reach. caller half: ahbode/infrastructure,
        provision/aws.infra/account=camp/resources.reach.ts"
   and  ^ THIS is the artifact that reaches the cut actor: a file on disk,
        readable with no aws credential at all

  when [t3] the paired half merges and applies
  then the same [t1] call succeeds, with no change on this side
```

## how the sharp edge fails safe

| obligation | how it holds |
|------------|--------------|
| **fast** | the denial lands on the first sts call, before any demo work starts. no partial run, no half-written state |
| **loud** | `AccessDenied` is an error, never a silent empty result. the aws sdk throws; the suite aborts |
| **teaches the fix** | 🔴 **this is the one that does NOT come for free**, and it needs the right artifact for the right reader — see below |
| **the limit holds** | a `target-only` world grants no partial power. there is no half-session, no degraded credential — the reach is either whole or absent |

### 🔴 the obligation, and the reader-reach trap inside it

aws's own message names the caller and stops, so the fix must be carried by **our** artifacts. the
trap is that the obvious artifact does not reach the actor who was cut:

| artifact | reader it reaches | needs a demo credential? |
|----------|------------------|-------------------------|
| the role's `description` | the provisioner, an auditor, anyone with `iam:GetRole` in demo | 🔴 **yes** — so it does NOT reach the stranded clone |
| a note in `provision/aws.auth/account=demo/` | **the clone**, from the checkout it is already in | ✅ **no** — a file on disk |
| the paired repo's own docs | a clone on the ahbode side | ✅ no |

⇒ **the design obligation this case creates: BOTH artifacts are owed, and the repo-side note is the
load-critical one.** the description serves the party with access; the checked-out note serves the
party without it, and the party without it is precisely the one `[t1]` cut.

⚠️ **and the general rule under it: a fail-safe is only as good as the artifact that carries its
explanation, so that artifact must be readable BY THE ACTOR WHO WAS CUT.** an explanation gated
behind the very access the failure denied is a fail-safe that fails safe for everyone except the
person who hit the edge.

## what the two forms each caught

- the **narrative** caught the *misdirection* — the error is technically accurate and
  psychologically off-target. no assertion expresses "this message will send you to the wrong repo".
- the **`[tn]`** caught `[t0]`, which the narrative skipped: the provisioner's re-plan reads **KEEP
  everywhere** in exactly this broken world. that is the sharpest fact in the case, and it surfaced
  only once the timeline forced a `when` for the plan.
