## the narrative

a reviewer opens the pull request that adds the grove's role. they do what a reviewer does with a
diff that touches iam: they scroll straight past it, down to the checks. `test-integration` is green.
they do not open it, because it holds no surprise to find — the run federated onto
`ehmpathy-demo-oidc` and passed exactly as it did yesterday, and a green check that looks like
yesterday's green check tells them the one fact they came to learn.

⚠️ **the lived moment is the absence of a second look.** the reviewer never has to ask *"did this
widen cicd?"*, and that unasked question is the whole experience — a guarantee felt as a
non-interruption, never as a result.

why does a non-event need a case at all?

because there is a shortcut that looks like the fast path and is the trap: bolt a second trust
statement onto `ehmpathy-demo-oidc`. one role, two principals, done in four lines. the paired repo
forbids it outright — *"never one shared with cicd — so a widen for one consumer can never silently
widen the other"* (`provision/aws.infra/account=camp/resources.reach.ts:24-26`) — and that rule lives
in a repo whose reviewers will never look at this diff. so the rule binds us with no reviewer to
enforce it.

what the shared role would cost is delayed and invisible. it would not break today. it would break
the day someone widens the grove's grant for a grove reason, and quietly widens what a github
workflow can do in demo — a change whose reviewer sees one consumer named in the diff and has no way
to know there are two.

the dedicated role buys four properties, and all four surface only later: an honest name, an
unentangled blast radius, a cloudtrail identity that tells a grove from a pipeline, and a revocation
that never edits a live cicd trust policy.

### 🔴 and one it does NOT buy — stated, because the shortcut's own argument demands it

the paired repo's reason for the rule is *"a widen for one consumer can never silently widen the
other."* under F1 — reuse `demoPermissionsPolicy` unedited — **the dedicated role delivers that
property at the role layer and not at the bundle layer.**

| layer | isolated under F1? |
|-------|-------------------|
| trust policy — who may assume | ✅ two roles, two trust documents, no overlap |
| cloudtrail principal | ✅ `assumed-role/ehmpathy-demo-for-grove/…` vs `…-oidc/…` |
| revocation | ✅ an **upsert** of one trust policy touches no live policy of the other. ⚠️ **upsert, never delete** — `set.delete = null` on the role's dao (`case=7` `[t3']`) |
| role-layer attachments — a grove-only inline or managed policy | ✅ `unique = ['role', …]`, so the rows never collide |
| **the shared bundle's contents** | ⛔ **NO** — an edit to `demoPermissionsPolicy` moves **both** roles, in one commit |
| 🔴 **the runtime capability** | ⛔ **NO, and it is INVERTED** — the bundle carries `iam:UpdateAssumeRolePolicy` on `'*'`, so the credential this grant issues can rewrite `ehmpathy-demo-oidc`'s **own** trust policy (`case=5` `[t2']`) |

⇒ this is no defect in the dedicated role; it is the **cost of F1**, and it means the wish's
"dedicated" constraint is honored in **letter and in part of its spirit, not all of it.**

🔴 **and the two unclosed layers close differently — they are not one gap with one shape.**

| the unclosed layer | what closes it | its cost |
|---|---|---|
| the shared bundle's contents | **only** a bundle with no `iam:` writes | ⛔ breaks the suite on day one |
| the runtime capability | ahbode's **spread + append** bundle function (`resources.reach.ts:69-99`) — spread the shared statements, append a `Deny` scoped to the oidc role's arn | one expression, or one small function. ⚠️ **rests on open question 7**, unverified |

⚠️ **this passage previously read *"the ONE shape … is a grove-specific bundle — precisely the
alternative F1 weighed and declined … a cost it must price."*** three parts of that were falsified
and are corrected above: the fork has **three** branches rather than two, F1 **never weighed** the
third, and the cost F1 declined them on was **retracted** — every option declares the same resources
(F5 already commits to the attachment), so they differ only in the `document:` value. raised to the
wisher as open question 1.

## the `[tn]` timeline

```gherkin
given [case4] ehmpathy-demo-for-grove is live in the demo account
  and  ehmpathy-demo-oidc is live, as it was before this wish

  when [t0] a pull request runs the test workflow
  then it federates onto ehmpathy-demo-oidc via sts:AssumeRoleWithWebIdentity
   and its trust policy still holds exactly one statement
   and that statement's principal is still { federated: '<the github oidc provider arn>' }
   and no { aws: ... } principal was added to it

  when [t1] the workflow runs the demo-account suites
       $ rhx git.repo.test --what integration --mode apply
       $ rhx git.repo.test --what acceptance --against cloud ...
  then both pass, with the same permissions they held before
   and  ^ they read demoPermissionsPolicy, which this wish did not edit

  when [t2] a future change widens the GROVE's grant AT THE ROLE LAYER
       (a new attachment, or a grove-only inline statement)
  then ehmpathy-demo-oidc's effective permissions do not move
   and  ^ the isolation a dedicated role buys, and the only [tn] that
        distinguishes a dedicated role from a shared one

  when [t2'] a future change widens the grove's grant BY AN EDIT TO demoPermissionsPolicy
  then 🔴 ehmpathy-demo-oidc's effective permissions DO move, in the same commit
   and  ^ THE HONEST LIMIT. under F1 the two roles read one bundle, so the
        shared-bundle layer is NOT isolated — only the role layer is.
        see the limit section below

  when [t3] the grove reach is revoked
       (the trust statement on ehmpathy-demo-for-grove is deleted, or the role is)
  then no edit lands on any live cicd trust policy
   and cicd keeps its access through the revocation
```

## what the two forms each caught

- the **narrative** caught the *temptation* and its delay: the shared-role shortcut is cheaper today
  and expensive on a day nobody can schedule. a `[tn]` cannot express "this defect arrives later".
- the **`[tn]`** caught `[t2]` and `[t3]`, which the narrative had only argued for. those two are the
  **only** steps where a dedicated role and a shared role differ observably — so they are the
  assertions that actually test the decision, rather than restate it.

## the limit it holds

`ehmpathy-demo-oidc`'s trust policy holds **exactly one** statement, before and after. that count is
the mechanical form of *"a reach owns its target"*, and it is checkable in a plan diff (`case=3`
`[t0]`).
