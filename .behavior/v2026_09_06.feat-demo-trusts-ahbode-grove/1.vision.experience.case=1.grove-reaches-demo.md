# case=1 — a grove-clone reaches demo

**cells** · `grove-clone × {obtain, act} × both`
**feel** · **graded per cell — see below**  ·  **care** · **critipath**  ·  **boundary-density** · 4

🔴 **the feel is SPLIT, and one header grade cannot carry it.** `[t6]` walks the suite **die
mid-flight** on an expired credential — a cut, on the wish's central path, inside a case whose other
cells promise no edge.

| cell | feel | why |
|---|---|---|
| `grove-clone × obtain × both` | **happy** | `[t0]`–`[t3]`. the assume-role succeeds and the suite starts. no edge |
| `grove-clone × act × both` — **short run** | **happy** | `[t4]`. the suite runs green and finishes inside the session's life. ⚠️ `[t5]` bounds the same cell — *integration* work reaches demo from a grove, *acceptance* does not |
| 🔴 `grove-clone × act × both` — **run ≥ session life** | **sharp** | `[t6]`. `ExpiredToken` mid-suite, `afterAll` dies on the same dead credential, and the orphans leak. its fail-safe is below |

⚠️ **the cells are unchanged; only their grade is.** this is one experience with a duration-keyed
edge, never two experiences — so it stays one case, and `case=_` carries the same split rather than a
new row. ⇒ **a case that spans a range can be happy at one end and sharp at the other, and a single
header feel hides exactly that.**

### how the sharp end fails safe

| obligation | how it holds |
|---|---|
| **fast** | ✅ `ExpiredToken` at the first call past the cap — the sdk raises at the boundary, never deep in a retry |
| **loud** | ✅ an explicit aws error, never a silent degrade. ⚠️ **and the loudness is what makes it survivable**: the failure names its own cause |
| **teaches the fix** | ✅ `[t6]` names it — an ini profile with `role_arn` + `credential_source = Ec2InstanceMetadata`, which the sdk **auto-refreshes**. local config, no `src/` change |
| **the limit holds** | ✅ a run that fits inside the cap completes in full. the edge is at the cap, never before it |
| 🔴 **no silent drop** | ✅ **it holds — by TWO declared controls, and it holds ONLY because they are named.** the run does leak real EC2 instances and VPCs, because `afterAll` holds the same dead credential. **but the leak is caught twice**, and both catchers are already in this repo — see below. ⚠️ **the residual is narrower than "the orphans drop silently"**: they are silent only *below* a cost threshold, and bounded above it |

### 🔴 the two controls that catch the leak — both already declared in this repo

the obligation is **answered**, by two controls already live in this repo — never named, priced, and
deferred:

| control | where it is declared | what it catches |
|---|---|---|
| **the next run's `beforeAll` sweep** | `rule.require.ec2-test-cleanup-both-ends`, `…vpc-test-cleanup-both-ends`, `…ssm-session-cleanup-both-ends` — a repo convention, enforced at blocker severity | the orphans, on the next run. ⚠️ **it needs a live credential**, which is exactly what question 17's ini profile supplies |
| 🔴 **the budget alerts + the cost-anomaly monitor** | `provision/aws.infra/account=demo/resources.budget.ts:55-89` — notifications at **50 / 80 / 100 %**, and an anomaly monitor at **$10** | a leak that outlives the sweep. it emails `OPS_EMAIL`. ⇒ **the drop is not silent past a cost threshold** — which is the precise sense the obligation asks about |
| **`guardBlockNew` — the deny-SCP** | `…resources.budget.ts:187-206` — `APPLY_SCP_POLICY` at 100 % actual, `AUTOMATIC` | the leak's **growth**. it attaches a deny-SCP to the whole demo account, so an unswept leak cannot run without bound. ⚠️ blunt: account-wide, and it stops legitimate work too |

⚠️ **and one control that does NOT reach this edge, stated so it is not miscounted.** `guardKillActive`
(`…resources.budget.ts:211-224`) would stop instances at 110 %, but it is **not armed** —
`instanceIds: []` — and it names one box (`declastruct-demo-box`) rather than arbitrary orphans. ⇒ it
is no part of this fail-safe.

⇒ **the obligation holds at rungs 3 and 4 of `rule.prefer.prevent-over-correct`** (catch it early,
report it well), never at rung 1. the prevention — the auto-refresh profile — **removes the edge
entirely** rather than handles it, and it is owed at execution regardless of what question 17
measures. ⇒ **question 17 decides whether it is urgent, never whether it is owed.**

🔴 **the general form: a fail-safe declared in `provision/` is invisible to a walk that reads only
`src/` and the behavior tree.** the budget stack has been live in the demo account throughout, and no
case cited it. **the census of what contains an edge must include the provision tree.**

> the reason the wish exists. if this path breaks, the grove cannot do demo work at all, and the
> only fallbacks are the two this wish exists to retire: hand-carry a credential onto the box, or
> move the work off the box.

## the narrative

a clone wakes on an ahbode camp grove. it holds one credential and it never asked for it — the box's
instance role, ambient in IMDS. that badge reaches ahbode prep and ahbode prod. it has never heard
of ehmpathy.

the clone is asked to run `declastruct-aws`'s integration suite. before this wish, that ask stalled:
the clone would have to say *"I have no way into the demo account"*, and a human would either paste a
keyrack credential onto the box or move the work to a laptop.

now it mostly just works. the clone runs one `sts:AssumeRole` against a role name it can read
straight out of this repo, exports the three returned values plus `AWS_REGION`, and the **integration**
suite runs. no key was shipped to the box. no rotation is owed to anyone.

⚠️ **and *"no profile was written"* does NOT belong on that list — `[t6]` is why.** a raw env-var
session is **static**, so the sdk cannot renew it, and the suite's runtime is the same order of
magnitude as the session's 1h life. the durable shape is an ini profile with `role_arn` +
`credential_source = Ec2InstanceMetadata`, which the sdk **auto-refreshes**. ⇒ **"not one secret"
survives a profile** — it holds a role arn and an instruction to read IMDS, and no secret — **so
claim the secret, never the file.** the file claim is both weaker and false.

⚠️ **"mostly" earns its place, and the limits are named rather than smoothed over.** the region
export is not optional — `getCredentials` fail-fasts without one, and a grove box has no
`~/.aws/config`. and the **acceptance** suite is out of reach: it drives the declastruct CLI, whose
fresh process reaches for **keyrack**, a vault the grove does not have. so this wish delivers demo
*integration* work from a grove, and not demo *acceptance* work. `[t3]` and `[t5]` walk both.

🔴 **and the integration half is CONDITIONAL, which an earlier pass recorded as verified.** the check
that produced *"no keyrack vault is consulted on this path"* read the **operation**
(`getSampleAwsApiContext` → `getCredentials`) and stopped there. one layer up,
`jest.integration.config.ts:28` wires `jest.integration.env.ts` as a setup file, and that file calls
`keyrack.source()` at `:63-65` before every integration test. ⇒ **a vault IS consulted.** the suite
survives only if `mode: 'lenient'` degrades when the vault is absent, which is **unchecked** — open
question 16. see `[t4]`.

the moment it clicks: **the clone received not one secret.** the grant is **declared in files**, in
the repo that owns the account. the credential materialized because a policy said the grove's badge
counts here — and edit those declarations tomorrow and the reach ends, with no key to hunt down.
⚠️ **"those declarations" is plural on purpose** — the trust policy answers *who may assume*, the
attachments answer *what the holder may do*, and a revoke needs both (`case=7`).

## what the two forms each caught

- the **narrative** caught the *value*, which no assertion states: the clone was handed **not one
  secret**, and that absence is the whole point. a `[tn]` alone would have read as "assume-role
  works", which is a mechanism, never a benefit.
- the **`[tn]`** caught two `given`s the narrative glossed: this path needs **both** halves live, and
  the clone's ambient identity must be the *camp grove role specifically* — a NAT box or a laptop on
  the same network holds a different badge and gets `AccessDenied`. it also forced `[t1]`'s
  expiration and principal-arn assertions, the two containment claims `case=5` leans on.

## the seams it crosses

1. **IMDS → sts** — the ambient badge must be the exact principal the trust statement names
2. **camp account → demo account** — the cross-org assume-role
3. **caller half → target half** — the pair that must both be live (`case=2` is this seam broken)
4. **session → suite** — the exported credential must carry the power the suite needs (`case=5` is
   this seam's cost)
