# 1.vision — authorized-ssh-key get reflects the box, via instance-identity binding

## the one-liner

today `getOneEc2SshKeyAuthorizedByUnique` asks "does the SSM **param** exist?" — and the param is
keyed by the box's stable `exid`, so it outlives a terminate-and-recreate. after a rebuild the get
reports a key the fresh disk does not carry, reconcile reads KEEP, `set` never re-lands it, and the
crew is locked out. the fix: **bind the tracked param to the box's instance-id; at get, compare the
recorded instance-id to the live one — a mismatch (a rebuild) reads as absent → CREATE.** the check
is answered from control-plane reads alone (`DescribeInstances` + `GetParameter`) — we NEVER connect
into the box to verify the key.

## the hard invariant (persisted)

this fix obeys a hard invariant now recorded at
`.agent/repo=.this/role=any/briefs/rule.forbid.in-guest-connection-for-drift-check.md`:

> a plan-time drift/existence check for a box-hosted resource must NEVER require a connection INTO
> the box (SSH, SSM `SendCommand`). when the true state lives inside the box, bind a
> control-plane-readable marker to the instance identity so a rebuild is detected from metadata.

option a in the original wish (probe `authorized_keys` over SSM from the read path) is REJECTED by
this invariant — it would connect into the box on every plan. option b (identity binding) is the
chosen shape.

## the outcome world

### day-in-the-life

an ahbode operator runs `git.grove.rebuild grove-1`. the box is terminated (with its immutable
launch template) and re-applied under the SAME exid `grove-1`, on a fresh 250GB disk and a NEW
instance-id. the operator runs `ssh grove-1`.

- **before (1.9.0):** `Permission denied (publickey)`. the fresh box has `camper` but an empty
  `authorized_keys`; the param `/declastruct/ec2/ssh-keys/grove-1/vlad-pop-os` persisted from before
  the rebuild, so the get said "key present" → reconcile KEEP → `set` skipped → no key on disk. the
  operator had to manually `aws ssm delete-parameter …` and re-apply. every rebuild carried this
  hidden manual step.
- **after (this fix):** the reconcile get reads the param, sees its recorded instance-id (`i-OLD`),
  reads the live instance-id (`i-NEW`) from `DescribeInstances`, and — mismatch — returns `null` →
  reconcile decides CREATE → `set` re-lands the key AND re-stamps the param with `i-NEW` →
  `ssh grove-1` succeeds. the operator does nothing special, and declastruct never touched the box's
  OS to figure this out.

### before/after contrast

| step | box disk | param's recorded instance-id | live instance-id | get decides — before | get decides — after |
|------|----------|------------------------------|------------------|----------------------|---------------------|
| first authorize | key present | `i-AAA` | `i-AAA` | (create) | (create) |
| box stop/start | key present (EBS + id persist) | `i-AAA` | `i-AAA` | KEEP ✅ | KEEP ✅ (ids match) |
| **box rebuilt (same exid)** | **empty (fresh disk)** | **`i-AAA` (stale)** | **`i-BBB`** | **KEEP ❌ (lie)** | **CREATE ✅ (id mismatch)** |
| key edited out-of-band, same box | absent | `i-AAA` | `i-AAA` | KEEP ❌ | KEEP ⚠️ (not caught — accepted) |

### the "aha" moment

the value clicks when the sticky note learns to name WHICH machine it was for. the param stops
being "a key was authorized here" and becomes "a key was authorized on machine `i-AAA`". the moment
the machine's serial number changes, the note is self-evidently void — and we learn that from the
machine's registration papers (`DescribeInstances`), never by knocking on its door.

## user experience

### whose experience

two non-human "users", both routed through the SAME get:

1. **declastruct's reconcile engine** — calls the DAO's `get.one.byUnique` at plan time for
   CREATE / KEEP / UPDATE.
2. **the DAO's `set.findsert`** — calls the get first; a non-null find returns early, a null find
   proceeds to re-push.

a single change at the get reaches both.

### the contract

```ts
// unchanged signature, corrected null-decision
getOneEc2SshKeyAuthorizedByUnique(
  { by: { unique: { instance: { exid }, comment } } },
  context,  // ContextAwsApi & ContextLogTrail
): Promise<HasReadonly<typeof DeclaredAwsEc2SshKeyAuthorized> | null>
```

- **input:** unchanged.
- **output:** unchanged type. what changes is WHEN it returns `null`: now `null` means "the param's
  recorded instance-id does not match the live box (or no live box)", not merely "the param is
  absent".
- **`set` gains one field:** it records the live instance-id into the param value (beside
  fingerprint / authorizedAt). no contract-shape change — the value JSON simply carries an
  `instanceId`.

### timeline (the rebuild path — the actual incident)

1. `setEc2SshKeyAuthorized` authorizes `vlad-pop-os` on `grove-1` (`i-AAA`) → key on disk + param
   value carries `instanceId: i-AAA`.
2. `git.grove.rebuild grove-1` → terminate + immutable template → re-apply → fresh box, same exid,
   NEW id `i-BBB`, empty disk, param untouched (still `i-AAA`).
3. `declastruct apply` → reconcile get: param `i-AAA` vs live `i-BBB` → **mismatch → `null`** →
   CREATE.
4. `set.upsert` (or findsert, now that find returns null) re-appends the key AND re-stamps the param
   with `i-BBB`.
5. `ssh grove-1` → in.

## mental model

### how a user would describe it to a friend

> "the provisioner kept a sticky note saying 'key authorized'. after a rebuild the note stayed but
> the new machine forgot the key, so it got skipped and we were locked out. now the note also writes
> down the machine's serial number — and it checks that serial against the live machine's papers. if
> the machine was swapped, the note is void and the key gets re-added. and it figures all this out
> without ever logging into the machine."

### analogies / metaphors

- **the serial-numbered receipt.** the param is a receipt; now it records the machine's serial. a
  receipt for a machine that no longer exists is void on its face — no need to inspect the machine.
- **registration vs a house call.** we read the machine's registration (`DescribeInstances`) to know
  if it was replaced, rather than make a house call (SSH/SSM) to inspect its contents.

### terms — theirs vs ours

| they say | we say |
|----------|--------|
| "the key" / "SSH access" | `DeclaredAwsEc2SshKeyAuthorized` |
| "the machine" / "the box" | the EC2 instance, referenced by stable `exid` |
| "the machine's serial number" | the **instance-id** (`i-…`), ephemeral — new on every rebuild |
| "the sticky note" | the **track layer** — SSM param, now carrying the instance-id it was written for |
| "check the serial against the papers" | compare the param's recorded instance-id to the live `DescribeInstances` id |
| "it re-added the key" | reconcile decided CREATE → `set` re-landed the key + re-stamped the param |

## evaluation

### how well it solves the goal

it fully solves the ACTUAL incident (a rebuild locks out the crew), and does so within the hard
invariant — no connection into the box. the get's `null`/non-null decision becomes a function of a
control-plane instance-id compare, which is exactly the signal that distinguishes a rebuilt box from
the one the key was applied to.

### pros

- **honors the hard invariant** — the check is answered from `DescribeInstances` + `GetParameter`
  alone; declastruct never connects into the box to verify a key.
- **works on a STOPPED box** — `DescribeInstances` reads a stopped/terminated box's metadata, so a
  plan never stalls on reachability. (a box-probe could not.)
- **no new IAM on the read path** — needs only `ec2:DescribeInstances` (every caller of the get
  already does instance lookups) + `ssm:GetParameter`. NO `ssm:SendCommand` on reads → the wish's
  IAM release-note concern disappears.
- **fast + no hang** — two cheap control-plane reads; no send-command poll, no agent-not-ready
  retry loop.
- **the rebuild-detection is PURE logic** — a `isEc2SshKeyAuthorizedStale({ recorded, live })`
  transformer is genuinely unit-testable, so the wish's "unit test" ask (acceptance #5) becomes real
  rather than an integration-only compromise.
- **tight correspondence, no spurious re-push** — an instance-id changes only on rebuild, which
  always wipes the disk; stop/start preserves both. so a mismatch is never a false alarm.
- **no orphan accumulation** — the instance-id lives in the param VALUE, so there is exactly one
  param per (exid, comment); a rebuild overwrites the value, it does not spawn a new param. (a
  scheme that put the id in the param NAME would orphan the old param on every rebuild — avoided.)
- **additive, minor release** — contract shape unchanged; a genuinely-matching box still reads KEEP.

### cons / the accepted tradeoff

- **a same-box out-of-band edit is NOT caught.** if `authorized_keys` is manually wiped while the
  instance-id is unchanged, the compare matches → KEEP → the get does not catch it. this is the
  deliberate trade for never touching the box (recorded in the invariant brief). recovery is a
  manual re-apply (idempotent). the actual incident (a rebuild) is fully covered.
- **an exotic same-id disk-swap is also not caught.** if someone stops the box, swaps the root
  volume for a fresh one, and starts it under the SAME instance-id, the compare matches → miss. not
  the incident; same class as the out-of-band edit.

### edge cases & the pit of success

| situation | recorded id vs live id | verdict | why it is safe |
|-----------|------------------------|---------|----------------|
| first authorize (param absent) | n/a | `null` → CREATE | no marker yet |
| genuine KEEP (no rebuild) | match | return key (KEEP) | same box the key was applied to |
| stop/start | match (id + disk persist) | KEEP | `DescribeInstances` reads the stopped box; id unchanged |
| **rebuild (same exid, new id)** | **mismatch** | **`null` → CREATE** | the headline fix — id compare catches it, no box connection |
| box terminated, not yet recreated | no live instance | `null` → CREATE | no box; `set` then needs the box active (apply-order) |
| legacy param (no recorded id) | unverifiable | `null` → CREATE | forces a one-time re-push that upgrades the param format; benign (idempotent) |
| same-box out-of-band key wipe | match | KEEP ⚠️ | NOT caught — the accepted tradeoff |

## open questions & assumptions

### assumptions made

1. **instance-id changes ⟺ rebuild ⟺ fresh disk (for the rebuild path).** verified against AWS
   lifecycle: terminate+recreate mints a new instance-id + new root volume; stop/start and
   hibernate/resume preserve both. this is the load-bearing correspondence and it holds for
   `git.grove.rebuild` (terminate + recreate).
2. **`set` has the live instance-id to record.** true — `setEc2SshKeyAuthorized` already looks the
   instance up (`getEc2Instance`, uses `instance.id`) before it acts, so recording it in the param
   value is a field addition, not a new lookup.
3. **`get` can read the live instance-id cheaply.** true — `getEc2Instance` by exid returns
   `HasReadonly<DeclaredAwsEc2Instance>` with `.id` from a single `DescribeInstances`
   (`castIntoDeclaredAwsEc2Instance.ts:75`), and works on a stopped box.

### questions — triaged

each tagged **[answered]** (settled now), **[research]** (research phase), or **[wisher]**.

1. **[answered] "unit" vs integration test classification.** under identity binding the
   rebuild-decision is PURE logic — extract `isEc2SshKeyAuthorizedStale({ recorded, live })` and
   unit-test it directly (no remote boundary). the full get stays integration; the CORE decision is
   genuinely unit-testable. the wish's acceptance-#5 "unit" ask is now satisfiable for real.
2. **[answered] test file name.** fold the rebuild case into the extant
   `ec2SshKeyAuthorized.integration.test.ts` (it already owns the instance-resume scene) rather than
   add a new `.journey.` file.
3. **[answered] option a vs b.** RESOLVED by the wisher (this conversation) + the hard invariant:
   ship option b (identity binding), NOT option a (box probe). option a is forbidden — it connects
   into the box.
4. **[answered] IAM.** no new grant needed — the read path adds only `ec2:DescribeInstances`
   (already held by every caller that looks up instances) + the extant `ssm:GetParameter`. the
   wish's `ssm:SendCommand`-on-read release note is MOOT under option b.
5. **[wisher] acceptance-#1 reframing.** the wish's acceptance #1 ("param exists BUT
   `authorized_keys` lacks the key line → null") is written for option a. under option b it is
   reframed to "param's recorded instance-id ≠ live box → null"; a same-box key-line removal is NOT
   caught. confirm this reframed acceptance is what you want (it fully covers the rebuild incident,
   trades away same-box out-of-band edits).
6. **[answered] rebuild-clamp scope.** RESOLVED by the wisher (this conversation: "cheaper tests are
   fine"): the clamp is a unit test of `isEc2SshKeyAuthorizedStale({ recorded, live })` PLUS an
   integration test that seeds a param with a mismatched instance-id and asserts the get returns
   null → CREATE. NO real terminate-and-recreate journey is required.

### to validate externally

- **[research] none — no new external dependency.** the fix uses `DescribeInstances` +
  `GetParameter`, both already exercised across the repo. no new API.

## groundwork

### external research

none — no new external dependencies. the fix uses AWS EC2 `DescribeInstances` (already driven by
`getEc2Instance`) and SSM `GetParameter` (already driven by `sdkSsm.getOneParameter`). no in-guest
SSM `SendCommand` is added — indeed the point of option b is to AVOID it.

### internal research (verified)

- **the defect** — `getOneEc2SshKeyAuthorizedByUnique.ts:22-37`: reads the param, returns `null`
  iff the param is absent, casts otherwise. it never looks up the instance and never compares an
  instance-id. confirmed.
- **`set` already holds the instance-id** — `setEc2SshKeyAuthorized.ts:31-34` looks up the instance
  and uses `instance.id`; the param value it writes (`:86-92`) does NOT yet carry `instanceId` —
  that field is the additive change.
- **`get` can read the live instance-id cheaply** — `getEc2Instance` by exid returns `.id` from one
  `DescribeInstances` (`getEc2Instance.ts:73-79, 100`; `castIntoDeclaredAwsEc2Instance.ts:75`), and
  its filter includes `stopped` (`getEc2Instance.ts:58-61`) so it reads a stopped box. confirmed —
  this is what makes the compare work without box connectivity.
- **the reconcile + findsert coupling** — `DeclaredAwsEc2SshKeyAuthorizedDao.ts:24-52`: both
  `get.one.byUnique` and `set.findsert` route through the get; a get-level null-decision reaches
  both. confirmed. the DAO logic itself needs no change.
- **the cast** — `asEc2SshKeyAuthorized.ts`: casts the param value → domain object, and already
  tolerates a legacy value missing a field (defaults `user`, `:31-32`) — the same tolerance pattern
  applies to a legacy value missing `instanceId`. confirmed.
- **instance-id preserved across stop/start** — `ec2SshKeyAuthorized.integration.test.ts:230-269`
  (case2) proves the key survives stop/start; the instance-id likewise persists (only
  terminate+recreate mints a new one), so a stop/start correctly reads KEEP. confirmed.
- **the governing invariant** — `.agent/repo=.this/role=any/briefs/rule.forbid.in-guest-connection-for-drift-check.md`
  (persisted this session) — forbids option a's box probe and prescribes the identity bind. it
  reconciles with `rule.require.immutable-source-of-truth` (read live truth, but via the control
  plane).

### vocab / patterns to reuse

- **"track layer"** — the SSM param; now it also records the instance-id it was written for.
- **`rule.forbid.in-guest-connection-for-drift-check`** — the new hard invariant; cite it in the
  fix's comments.
- **`rule.require.immutable-source-of-truth`** — the sibling rule; the instance-id is the live,
  control-plane-readable truth the compare reads.
- **the legacy-tolerant cast** — mirror `asEc2SshKeyAuthorized`'s missing-field default for a param
  value that predates the `instanceId` field.

## what is awkward

1. **the accepted blind spot.** a same-box out-of-band edit of `authorized_keys` is not caught. it
   is the deliberate price of the invariant, and it is genuinely rare versus the rebuild it fixes —
   but a reader must not mistake the KEEP-on-same-box-edit for the original bug. the fix's comment
   must state that existence is proven by instance-identity match, NOT by the key line, and cite the
   invariant brief so the tradeoff is legible.
2. **an ephemeral value inside a stable-keyed marker.** the param NAME stays keyed by the stable
   exid (so it stays a single, stable param), while its VALUE now carries an ephemeral instance-id
   that a rebuild invalidates. that "stable name, ephemeral inner id" split is a small subtlety —
   but it is exactly what avoids orphan-param accumulation, so it is the right shape.
3. **acceptance reframed from the wish's letter.** the wish's acceptance #1/#2 speak of "the key
   line on the box"; option b speaks of "the recorded instance-id vs the live box". the OUTCOME the
   wish cares about (the rebuild path re-pushes) is fully met, but the literal acceptance phrasing is
   superseded — flagged for wisher confirm (open question #5).
4. **the CREATE-on-rebuild decision is proven at the domain + integration grain, NOT at the
   acceptance/CLI grain — a DELIBERATE deferral.** the reconcile decision (stale id → `null` →
   CREATE) is clamped three ways: the pure `isEc2SshKeyAuthorizedStale` unit, the mocked
   `getOneEc2SshKeyAuthorizedByUnique` orchestrator unit, and `ec2SshKeyAuthorized.integration.test.ts`
   case5 (seeds a mismatched instance-id, asserts the get returns `null` → CREATE). what is NOT added
   is an ACCEPTANCE case that seeds a stale `instanceId` and asserts `declastruct plan` reports
   CREATE for `DeclaredAwsEc2SshKeyAuthorized` via the CLI, with a CREATE-on-rebuild `.snap` variant
   beside the extant KEEP snapshot in `declastruct.acceptance.test.ts.snap`. this is deferred on
   purpose, for three reasons: (a) open question #6 was resolved by the wisher — "NO real
   terminate-and-recreate journey is required; the clamp is the unit + the seeded-mismatch
   integration test" — which the delivered coverage satisfies to the letter; (b) the acceptance suite
   drives the real `declastruct` CLI against live AWS, so this case needs the same interactive-SSO
   creds that gate the whole acceptance/integration real-infra pass (a foreman-only wall in CI); and
   (c) `declastruct.acceptance.test.ts` already carries a pre-extant comment that holds ssh-key-resource
   behavior verification out of the CLI suite in favor of `ec2SshKeyAuthorized.integration.test.ts`, so
   the deferral follows established repo precedent rather than a new pattern. recorded here (per the
   peer reviewer's recommendation) so a future reader sees the KEEP-only acceptance snapshot as a
   known, wisher-sanctioned tradeoff — not an oversight. the follow-up, if ever wanted, is one
   acceptance case that seeds the stale id via `sdkSsm` + a `declastruct plan` assertion of CREATE +
   its snapshot.
