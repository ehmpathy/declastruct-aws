# 1.vision.experience.dimensions

## .what

the orthogonal axes this wish's experience space varies over. the product of these axes is the
full space; `1.vision.experience.case=_.md` walks it and verdicts every cell.

## .the axes

### A — actor (2)

| value | who | their obligation to the resource |
|-------|-----|----------------------------------|
| `consumer` | an infra author who declares a bucket wish and runs `declastruct plan` / `apply` at a terminal. the `ahbode/infrastructure#35` human | **create it to KEEP.** the bucket outlives the run |
| `system:ci` | the acceptance suite. unattended — reads no prompt, iterates on no error, sees only a log line | 🔴 **create it to DESTROY.** every fixture it creates it must be able to tear down, unattended, with the demo role's own grants |

🔴 **the third column is the axis, and an earlier draft omitted it.** ci was defined purely by what
it *cannot read* — no prompt, no iteration, one log line — which is a claim about **error
legibility** and generates only "the message must carry the fix". it does not generate the
obligation that actually distinguishes the actor:

> **a consumer creates a bucket to keep. ci creates a bucket to destroy.**

that asymmetry is what makes `versions: 'Enabled'` a different experience for ci than for a
consumer — an enabled bucket that ever receives an object **cannot be emptied** by the demo role,
so the fixture becomes a globally-namespaced orphan. the cell is verdicted in the inventory's ci
modifier; the point here is that **no axis defined by legibility alone could have produced it.**

**orthogonal?** yes. either actor can meet any property, any desired value, any remote state. the
obligation column is a **property of the actor**, not a fifth axis — it does not vary independently.

⚠️ **has-human is NOT a separate axis.** `actor=system:ci` implies `has-human=no`, so a
`has-human` axis would be a function of A, not independent of it. it is folded into A
deliberately (`rule.require.dimensional-decomposition` — a value on one axis must not imply a
value on another).

### B — property (4)

the four properties the wish adds. each is a separate axis value because **each has a distinct
absent read**, and the absent read is what permadrifts.

| value | aws surface | absent read |
|-------|-------------|-------------|
| `versions` | `Get/PutBucketVersioning` | **empty body** — `Status` simply not returned |
| `publicAccess` | `Get/Put/DeletePublicAccessBlock` | **a 404** — ⚠️ error name UNVERIFIED, see c2 |
| `abortMultipart` | `LifecycleRule.AbortIncompleteMultipartUpload` | **an omitted sub-object** |
| `expireNoncurrent` | `LifecycleRule.NoncurrentVersionExpiration` | **an omitted sub-object** |

🔴 **the gerund exemption this line claimed was RETIRED by the council, 2026-09-09.** aws's own
symbols (`Put/GetBucketVersioning`) keep the api's letters because we do not own them; **our declared
resource is `DeclaredAwsS3BucketVersions`**, and `rule.forbid.gerunds` binds it with no exemption.
🟢 the axis-B position above is renamed to match — the council overruled **F12** the same day and
the conform was applied across the route.

**orthogonal?** yes to A, C, D, E. a cross-property dependency does exist (noncurrent expiry is
inert without versioning); it is not an axis — it is a **cross-cell invariant**, recorded as such
in the inventory.

### C — desired (2)

what the consumer's wish declares for that property.

| value | means |
|-------|-------|
| `value` | a concrete declared value (`'Enabled'`, a block config, `7`, `30`) |
| `null` | explicitly not wanted. `rule.forbid.undefined-inputs` bars an optional field, so `null` is always **typed out**, never merely omitted |

#### 🔴 `value` is a CATEGORY, not an atom — so its members are enumerated per property

⚠️ **added by peer review r1**, which held that *"a value that is a category rather than a closed set
of concrete meanings means the product is not truly decomposed at the atomic level, and a reviewer
cannot check completeness of the walk from the axis as written."* correct, and the file had conceded
the point for `versions` alone while leaving the general case unstated.

🔴 **`value` cannot be atomic, and that is structural rather than a defect to remove.** the concrete
value-space is a **function of B** — a bucket's versioning admits a two-member union, a day-count
admits an integer interval. to split C into concrete values would make a position on C imply a
position on B, which is the exact correlation A's own `has-human` exclusion bars. ⇒ **so C stays
`{ value, null }`, and completeness is made checkable the way axis D already does it: with a table
that states the closed member set per property.**

| property | the closed members of `value` | verdict per member |
|----------|-------------------------------|--------------------|
| `versions` | 🔴 **two** — `'Enabled'` ∣ `'Suspended'`, offered by the union with equal standing and forced explicit by `rule.forbid.undefined-inputs` | 🔴 **both members are DEMOED** — `'Enabled'` at cell 1 (c1), `'Suspended'` at **cell 3** (c3, `Enabled → Suspended`). what is itemized is **one TRANSITION**, not a member: `absent → 'Suspended'` (the first-set), ⚠️ revision trigger **A-9**. ⚠️ **corrected by peer review r1 (verified17, nitpick.2)** — an earlier pass wrote *"`'Suspended'` itemized"* flat, which mislabels a demonstrated value as an undemonstrated one **in the very table a reader uses as the completeness check** for this non-atomic category. ⇒ *a member's verdict and a transition's verdict are different claims; this column carries the member's* |
| `publicAccess` | **one meaning, two written forms** — see the encodings table below | **demoed** (c1); form (b) rides c1's obligation 4 |
| `abortMultipart` | **a positive integer** — the type says `number \| null`, so the type is **wider than the domain** | the interior **demoed** (c1) · the **edge** (`0`, negatives) itemized as the input-limit hazard |
| `expireNoncurrent` | **a positive integer** — same widening | same as `abortMultipart` |

⇒ **two rows carry a member the grid does not demo, and each is `itemized` rather than hidden:**
`versions`'s `'Suspended'` (revision trigger A-9) and the two day-counts' non-positive edge (the
sharp-edge locator's input limit). that is the completeness check the reviewer asked for — **a reader
compares the member column against the verdict column and sees exactly which members are itemized
rather than demonstrated.**

⚠️ **and the widening in the two integer rows is the reason the input edge exists at all.** a type of
`number | null` admits `0` and negatives that aws rejects, so the atomic-member view and the
sharp-edge view are the **same finding reached from two directions** — which is why the edge is owed
a construction guard rather than left to the api.

⇒ so cell 1 (`value | absent`) covers **two** declarations, not one, and the grid named only
`'Enabled'`. the second — `absent → 'Suspended'`, a consumer who declares suspension on a
never-versioned bucket — is carried in the inventory with its status **unverified**: aws's response
to it has not been read, and *"it fits the pattern"* is the exact move this drive has recorded as
the root cause of A-5, A-6 and A-7. it is named rather than guessed.

#### 🔴 `value` also has two ENCODINGS for `publicAccess` — the same trap as axis D, on this side

axis D carries a table of the wire shapes `absent` arrives in, because *a decomposition is total
over meanings, not over encodings*. **that question applies to C too, and one property fails it:**

| property | written form(s) of `value` |
|----------|-----------------------------|
| `versions` | one — a union member (`'Enabled'` ∣ `'Suspended'`; see the multiplicity above) |
| `publicAccess` | 🔴 **two** — (a) a spread of the preset const `s3BucketAccessPublicBlocked`, or (b) a bare four-boolean literal |
| `abortMultipart` | one — a number |
| `expireNoncurrent` | one — a number |

**why the two forms are not cosmetic.** the compare runs
`serialize(omitReadonly(remote)) === serialize(omitReadonly(desired))`, and `serialize()` tags a
DomainObject instance with a `_dobj` key while it never tags a plain literal. so the preset spread
and the bare literal serialize **differently** unless `access.public` sits in `static nested`
and hydration re-instantiates both operands before the compare. that is exactly what c1's
obligation 4 proves, and why F2's nested registration carries weight rather than mere layout.

🔴 **and F14 doubled the depth this must hold at.** `access: { public: {…} }` nests **twice**, so
`access` needs `static nested` on the bucket **and** `public` needs it on the access dobj — both with
a `.strict()` schema. a registration at one level only leaves the `_dobj` tag mismatch live one level
down, where it produces the identical permadrift with **half** the surface to notice it on.

⚠️ **the encoding the headline demo uses is (a); the one a consumer reaches for is (b).** c1's
narrative spreads the preset; a consumer who wants three of four booleans writes the literal. both
must land on the same cell.

⇒ note the shape difference from the multiplicity above: `versions` has **two meanings** under one
value (two distinct declarations), while `publicAccess` has **one meaning in two shapes**. they are
different failures and each needs its own check.

**orthogonal?** yes. any property can be desired or nulled, by any actor, against any remote state.
both non-atomicities above are **within-value** multiplicities, not correlations with another axis.

### D — remote (3)

what aws currently holds for that property.

🔴 **and it is RELATIVE to `desired`, by construction — an earlier pass claimed the opposite.**
⚠️ **corrected by peer review r1 (verified17, nitpick.1)**, which read *"read **absolutely**, not
relative to `desired`"* against the very next row's *"aws holds exactly the desired value"* and named
the contradiction. it is right, and the honest statement is the relative one:

| value | means | absolute? |
|-------|-------|-----------|
| `absent` | aws holds no value — **one sense, and it arrives in several wire shapes** (below) | ✅ **yes** — a fact about the remote alone |
| `set-same` | aws holds exactly the desired value, modulo canonicalization | 🔴 **no** — a comparison against C |
| `set-other` | aws holds a value that is not the desired one | 🔴 **no** — same |

⇒ **and the consequence is exactly the void the reviewer traced it to.** `null × set-same` (cells 5,
11, 17, 23) is a **definitional** collision — *"aws holds exactly the value I declared, and the value
I declared is `null`"* is a contradiction in the axis's own terms, not a fact about aws.

🔴 **so the verdict carries the `(frame)` qualifier, and that label exists because of this paragraph.**
⚠️ **this text read *"its `impossible` is nature relative to this decomposition, never nature in the
world"* while the cells were labelled `impossible (nature)`** — a concession in the prose and its
contradiction in the verdict, which is precisely the shape peer review r1 has now caught six times.
verified22 named it, and the fix was to give the label the distinction the prose already drew:
`impossible (frame)` for a void **our decomposition** creates, `impossible (nature)` for one the world
imposes. the two differ in who can retire them — see the census's qualifier table.

⚠️ **the walk is still total, and the reviewer says so** — the real experiences that a value-relative
D might have hidden are captured: a retract of a set property is `null × set-other` (cells 6, 12, 18,
24), which **is** demoed (c3) and forbidden-by-nurture (I-1). ⇒ **no experience falls through the
collision; what falls through is the claim that D reads absolutely.**

🔴 **why keep the relative frame at all, now that its cost is named.** an absolute D (`absent` ∣
concrete-A ∣ concrete-B) makes the impossibility genuinely checkable — the reviewer's recommendation,
and it is sound — but it also makes **every** cell's verdict depend on which concrete pair you picked,
and this wish's four properties have wildly different value domains (a 2-member union, a 4-boolean
object, two integers). ⇒ the relative frame is a **deliberate trade**: it buys one grid that spans all
four properties, at the cost of one definitional void per property. recorded here rather than defended
silently, so a later drive with one property can take the absolute frame knowingly.

#### 🔴 `absent` is one MEANING with several ENCODINGS — and THREE properties have two of them

| property | encoding(s) of `absent` |
|----------|--------------------------|
| `versions` | an **empty body** — no `Status` key. 🔴 **and F16 changed what that DEGRADES TO**: the canonical read is now **`false`**, a token, not `null` — so `versions` is the one property whose absent-read is a different *value* from its peers'. ⇒ *"absent" is a per-property contract, never a repo-wide constant* — see c2's repaired table |
| `publicAccess` | 🔴 **two** — (a) the **absent-signal error**, a 404 whose name is UNVERIFIED (see c2), **or** (b) a **present-but-empty `{}`**, a 200 with all four booleans undefined |
| `abortMultipart` | 🔴 **two** — (a) an **omitted sub-object** on a rule that WAS returned, **or** (b) **no lifecycle rule at all** — `getBucketLifecycle` raises `NoSuchLifecycleConfiguration` and there is no rule to omit a sub-object from |
| `expireNoncurrent` | 🔴 **two** — the same pair as `abortMultipart`; both sub-rules ride the one `GetBucketLifecycleConfiguration` call, so they share its absent-signal |

**why the two lifecycle properties have two.** ⚠️ **added by peer review r1, which found this row
listed one encoding while the file's own case set handled two.** `case=2` `[t2]` already matches
`NoSuchLifecycleConfiguration` — the *no-rule-at-all* shape — and c8 turns on the difference between
a rule that exists with no actions and no rule at all. so the second encoding was **live in the
corpus and absent from the grid**, which is this drive's repeat defect landing on the very table
written to prevent it.

⇒ **and the two shapes are not interchangeable for a detector.** `(a)` needs a per-sub-object read
on a returned rule; `(b)` needs an **error-name match** before any rule exists to read. a detector
written from the old single-shape row would have handled `(a)` and thrown on `(b)` — precisely the
failure mode this table's own lesson names.

**why `publicAccess` has two.** `PublicAccessBlockConfiguration` types all four booleans as
independently optional (`models_0.d.ts:10155-10182`), so an all-undefined `{}` is representable on
the wire — and it carries the same sense as the 404: *no block configured*. the repo already treats
this as real for a structurally identical sub-block: `asDeclaredAwsEc2InstanceMetadataOptions.ts`
ships an `isWhollyAbsent` predicate whose sole job is to fold *"key omitted"* and *"present-but-empty
`{}`"* into one absent read, because *"if an all-empty `{}` fell through to the per-sub-field
fallback below, it would read back fully SECURE and false-KEEP an imdsv1-allowed box"*.

⚠️ **the generalizable lesson, and the reason this table exists at all: a decomposition is total
over MEANINGS, not over ENCODINGS.** an earlier draft listed one encoding per property and read as
complete, because at the level of *sense* it was. the trap is that one sense can arrive in two wire
shapes, and a detector written from the grid handles the shape the grid named and throws on the
other.

**orthogonal?** yes to A, B, C. `desired=null × remote=set-same` is 🔴 **`impossible (frame)`** — "a
value equal to null" is `absent`, which is a different D value. the inventory marks those four cells
(**5, 11, 17, 23**) impossible with that reason.

🔴 ⚠️ **this line read *"impossible by nature"* until verified24, and *"a cell collision, not an axis
correlation"* with it.** both were superseded at verified22 — by the `(nature)` / `(frame)` split, and
by deviation **X-1**, which records that D **is** relative to C rather than orthogonal to it. the
regrade landed in the census and never reached this line. ⇒ **the tenth instance of this drive's one
class, and the fifth created by a repair** — caught by the route-wide grep for a retired term that the
census's own verdict-check prescribes, run for the first time this round. *a regrade is not done when
the cell is relabelled; it is done when every site that states the old label has been searched for.*

### E — concurrency / time (2)

⚠️ **this header read *"2 values in the product, 3 canonical values verdicted"*, and peer review r1
was right that the phrasing invites a blocker** — it declares a third position and then walks two,
which is the same shape as G's excluded slice. **E has exactly two positions**: `settled` and
`in-flight`. the canonical value `retried` is a **sequence over** those two, walked as a pass — see
`.the product` for the axis-versus-sequence distinction, stated once for both E and G.

this is the canonical **`concurrency / time`** axis `howto.experience.decompose` names — *"first vs
concurrent vs retried; this is the dimension that surfaces the non-narratable critipaths (races,
eventual consistency) a happy-path list skips."*

⚠️ **an earlier draft called this "read freshness" and claimed it was discovered by the walk.** the
walk did surface it — but it surfaced **one slice** of a canonical axis, named that slice as though
it were the whole, and then excluded "concurrency" separately as an axis the space did not have. the
axis is one; its values are three, and every one is verdicted here:

| canonical value | where it lives | verdict |
|-----------------|----------------|---------|
| `first` | folded into **axis D** as `remote=absent` — the first write against an unset property | ✅ taken, as a D value |
| `concurrent` | two writers at once | ⛔ **excluded** — the three-scenario walk below |
| `retried` | a second apply | ⚠️ **splits** — see below |

#### the two values E takes — the read-after-write window

| value | means |
|-------|-------|
| `settled` | the read happens outside aws's read-after-write window |
| `in-flight` | the read happens inside it — aws may still return the pre-write state |

**why it is real, with evidence.** `setS3Bucket.ts:66-84` already carries a poll loop that waits
for **3 consecutive stable reads** of the lifecycle config, with a comment that a single matched
read "can regress to null on the very next read". that loop is proof the window exists and bites.

**why it is orthogonal — and where it is NOT, stated plainly.** at `settled`, E is fully free: a read
is settled independent of who reads, which property, what was wanted, or what aws holds.

🔴 **at `in-flight` it is NOT, and this line claimed otherwise until verified20.** the section above
opens with the correlation itself — *"the window opens if and only if a WRITE is issued"* — so
`in-flight` is reachable only on the sub-region where a write is issued (`D ∈ {absent, set-other}`,
and for `B = versions` only where `C = value`). **that is the identical partial function axis F's
`write` value carries**, and the two are bounded by the same census modifier.

⇒ **E is per-value orthogonal, exactly like F.** the product-line caveat now marks both; see
`.the product`. the axis is kept because its **other** value carries the whole of `case=5` — a live
defect in shipped code — which no C × D coordinate could hold.

#### 🔴 why E multiplies by **2**, not 3 — `retried` is a SEQUENCE over E, not a position in it

⚠️ **raised by peer review r1** (dimensional-decomposition): the axis declared three canonical values
while the product line used `E(2)`, so the stated total was **not the product of the declared sets as
written**. the answer is structural, not a correction to the number — which is why the number has
since changed (axis F) and this argument has not.

`settled` and `in-flight` are **mutually exclusive** — a read is one or the other, never both — which
is exactly what a multiplicand requires. `retried` is **not exclusive with either**: a retry is a
*second run*, and that second run is itself settled or in-flight. so `retried` composes E **with
itself** rather than adding a third position beside them.

⇒ therefore, stated so the product and the census agree by construction:

- the set that **multiplies** is `{ settled, in-flight }` — 2 — and that is the `E(2)` in the product
- **`retried` is walked as a second pass over the same 24 cells**, not as a third multiplicand. its
  own table below splits by *what you retry FROM*, which is precisely the sequence-over-E shape

⚠️ **the alternative was weighed and rejected.** to declare `E(3)` would **double-count**: each
`retried` cell is already a `settled` or `in-flight` cell reached a second time, so a full **third**
of that product would duplicate the other two-thirds with no verdict of its own. a product that
contains the same experience twice is not a sharper census — it is a census that can no longer report
absence, which is the one thing the walk exists to do.

⚠️ **stated as a ratio deliberately.** an earlier draft wrote this as *"48 of the 144 would duplicate
the other 96"*, and those three absolute figures went stale the moment axis **F** was taken. the
argument never depended on them — it depends only on `retried` being one position among E's other
two — so it is now written in the form that cannot rot.

#### `retried` — two states to retry FROM, and only one is demoed

| retry from | verdict |
|------------|---------|
| a **converged** state — a clean second apply | ✅ **demoed** — c1 `[t3]`, and c2's re-plans |
| a **half-applied** state — the first apply threw partway | ⚠️ **itemized**, sharp · **alter** — see the inventory's modifier row |

🔴 **the half-applied retry carries a one-way door.** `setS3Bucket` is not atomic; if
`PutBucketVersioning` lands and a later write throws, the bucket is **versioned by accident**, and
invariant I-1 means the consumer cannot undo it — their natural next move (`versions: false`) is
rejected. its fail-safe is **c3's guard verbatim**, reached by a different route, so it crosses no
boundary c3 does not already cross and earns a verdict rather than a ninth case.
⇒ **the mitigation is a write ORDER**: issue the versioning put **last**. carried in `case=1` `[t1]`.

🔴 **F16 put a second half-applied state INSIDE one declared field.** `versions.status` goes out on
`PutBucketVersioning` and `versions.expire` on the lifecycle put, so a partial failure can now split
a **single field** — a shape the pre-F16 decomposition could not produce, since each field mapped to
one call. ⇒ the write-order mitigation still holds (**the version-state put goes last**, so the
one-way door is the last thing opened), and the modifier's verdict is unchanged. what changes is the
**unit** a reader must reason about: no longer *"which properties applied?"* but *"which HALVES of
which properties applied?"* — recorded as **I-7** in the census.

#### `concurrent` — excluded, and here is the walk

no path off it is new to this wish. three scenarios, checked against live code:

| scenario | what happens | new to this wish? |
|----------|--------------|-------------------|
| two applies race the same bucket | `assertPlanStillValid` hashes the **whole** changes array (`hashChanges.js:10-16`); a concurrent mutation between plan and apply → `BadRequestError('plan is stale')`, apply refused | **no** — a declastruct-level mechanism, invariant across every resource type |
| a second writer clobbers the lifecycle | the put is replace-all; the extant foreign-rule guard (`putBucketLifecycle.ts:38-60`, invariant I-4) fails loud on the read | **no** — extant; the two new sub-rules ride it unchanged |
| the multi-write is not atomic | `setS3Bucket.ts:48-96` issues `createBucket` → (`putBucketLifecycle` + poll ∣ `delBucketLifecycle`) → `reconcileS3BucketTags`; this wish adds **two more write surfaces** | ⚠️ **this one is real, and it is not a concurrency cell** — it is the `retried`-from-half-applied state above |

**what it surfaced.** the extant poll's predicate is `live?.transitions.length ===
desired.transitions.length`. a backup store declares **zero transitions** and only the two new
sub-rules — so that predicate matches on the very first read, before the write lands. the poll
would pass while the config had not settled. a real defect, found by the axis rather than by
memory.

### F — grant grain (2)

which class of aws call the run issues, and therefore **which iam grant it consumes**.

| value | the calls | the grant it needs |
|-------|-----------|--------------------|
| `read` | `GetBucketVersioning`, `GetPublicAccessBlock`, `GetBucketLifecycleConfiguration` | `s3:Get*` |
| `write` | `PutBucketVersioning`, `PutPublicAccessBlock` (+ `DeletePublicAccessBlock` under F11 option (a)) | `s3:PutBucketVersioning`, `s3:PutBucketPublicAccessBlock` |

🔴 **this axis was ABSENT, and the census confessed it as a `+1`.** an earlier draft walked
`A × B × C × D × E = 96` and then added the `system:ci` iam gate as *"one cell the product does not
generate"*, for **97 walked**. peer review r1 graded that a **blocker**, correctly:
`rule.require.dimensional-decomposition` states that **a real path off an absent axis is a blocker —
the space was under-decomposed**. the `+1` was never a curiosity worth preserved visibility; it was
the symptom, and it named its own cause in the same sentence.

⚠️ **the earlier defense was a rationalization, and it is recorded rather than deleted.** it argued
that to fold the cell in *"would falsify the product"* — which holds only if the axis set is held
fixed, and that is exactly what the rule refuses. the remedy the rule names is to **take the axis**;
the product then generates the cell rather than hold it as an exception.

**why it is orthogonal — and where it is NOT, stated plainly.** every one of A, B, C, D, E holds at
the `read` grain: either actor plans; each of the four properties has a `Get`; a `value` or a `null`
is read the same way; every remote state is read; and a read is settled or in-flight independent of
whether a write follows it.

⚠️ **one qualification on that list, added at verified21: D's freedom here is freedom WITHIN its own
relative definition, not absolute.** `C = null × D = set-same` is void at the `read` grain exactly as
it is everywhere else (deviation **X-1**), because D's positions are comparisons against C rather than
absolute remote states. the sentence above claims only that F's `read` value adds **no further**
constraint — it does not claim D is unconstrained.

🔴 **but `write` carries a within-value dependency, and an earlier pass overstated the proof.**
⚠️ **caught by peer review r1 (verified16, nitpick.2)**, and the reviewer is right: the old line read
*"any remote state can be read or written"*, while the census's own `F = write` modifier opens with
*"applies only where a write is actually issued, i.e. where the plan is not KEEP."* those two cannot
both be true.

| the `write` value is reachable only when… | so it depends on |
|---|---|
| a change is actually declared — a KEEP issues no call | **D** ∈ {`absent`, `set-other`} |
| the declared value is not the one I-1 bars — a null `versions` issues no `Put` at all | **C** = `value`, for `B = versions` |

⇒ **so `read` varies freely over all 24; `write` is a function of C × D on part of the grid.** the
honest statement is the one the C-axis multiplicity table already models: **an axis may be orthogonal
at one value and correlated at another**, and the census's job is to say which cells go vacuous rather
than to claim a clean product it does not have.

⚠️ **and this does NOT retire the axis** — the correlation hides no experience. it generates exactly
the cells the axis was taken for (**c6** at the write grain, **A-8** at the read grain), and the
vacuous cells are enumerated in the `F = write` modifier rather than swept. ⇒ **a correlated axis that
generates a real find is still owed a place; what it is not owed is a proof it cannot support.**

⚠️ **it is NOT the `phase` axis excluded below.** `phase` names a **position in a sequence**
(plan → apply → re-plan), and its third position correlates with D — after an apply, `remote` is
`set-same` by construction. **F names which grant the call consumes**, and is silent on sequence
position. the distinction is load-bearing rather than semantic: a phase carries no permission, so a
phase axis cannot generate the iam cells at all — which is why the space stayed under-decomposed
after `phase` had been weighed and dismissed.

#### 🔴 what the axis FOUND — it generates the two iam hazards as one table

the `+1` was a single cell. the axis generates **four**, and two of them are the wish's two known
iam hazards, which the vision had held as unrelated items in two different registers:

### the two kinds of structure, stated once so they stop being conflated

| kind | what it is | how it is walked |
|------|-----------|------------------|
| an **axis** | an independent variable with closed positions | **multiplies into the product**; every cell it generates carries a verdict |
| a **sequence over an axis** | a *transition between two positions* on one axis | **a pass over the product**, never a multiplicand — it names the cells whose verdict the transition changes |

⇒ this space holds exactly **two** sequences, and each is a transition on an axis already multiplied
in:

- **`E: settled → in-flight → settled`** — the **retry**. a retry is a *second run*, and each run is
  itself settled or in-flight, so a third E position would double-count.
- **`G: 1.11.0 → 1.12.0`** — the **upgrade**. an upgrade is a *move between* the two G positions,
  both of which the product already generates.

⚠️ **a sequence is not a value, and two headers said otherwise.** E's read *"3 canonical values
verdicted"* — a declared position that never entered the product — and G's buried the distinction in
its title. both now state `E(2)` and `G(2)` plainly, with the sequence named as a **pass**.

### the three layers

- the **core grid** — `B × C × D` = **24 cells**, each verdicted in full
- the **modifiers** — `A × E × F` = **8**, applied over the core with an explicit statement of which
  core cells each modifier changes and what the default is elsewhere
- 🔴 the **version slice** — `G` = **2**: one slice walked cell-by-cell, one verdicted whole

⚠️ **the three layers must multiply to the product line above, and a reader should check that they
do:** `24 × 8 × 2 = 384`. this arithmetic has now been corrected **three** times by review — on `E`,

## .the hidden-dimension check

per `rule.require.dimensional-decomposition`, a whole row or column that cannot occur signals a
latent axis. three were checked, and **the third was found by a different tell than the other two**:

1. **the `desired=null × remote=set-same` column is void across all four properties.** cause: a
   value-identity collision inside axis D, not a latent axis. D stays as-is; the four cells are
   marked impossible with the reason.
2. **the `expireNoncurrent` row reads oddly when `versions` is null** — the rule is legal in aws
   yet inert. cause: a **cross-property** dependency. it is not an axis (it is a relation between
   two values of B), so it is recorded as a cross-cell invariant instead. this is the check that
   caught the wish's headline `.why` — the cost leak.
3. 🔴 **a real cell that no coordinate generated** — the `system:ci` iam gate. cause: a **latent
   axis**, the permission boundary. ⇒ taken as **axis F**.

⚠️ **the third tell is the one this file missed for three rounds, and it is worth naming apart from
the other two.** checks 1 and 2 look for a **void** — a row or column that cannot occur. check 3
looks for the **inverse**: a cell that occurs and has no coordinate. both are latent-axis signals and
`rule.require.dimensional-decomposition` grades them very differently — a void is diagnostic, while
a real path off an absent axis is a **blocker**. ⇒ **a hidden-dimension check that scans only for
voids will pass a space that is missing an axis**, which is precisely what happened here.
