# case=10 — the upgrade seam defers the iam failure to an unrelated PR

**feel** sharp · **care** critipath · **actors** `consumer` **→** `system:ci` (the seam) · **cells** the A-axis join over 1, 2, 7, 8

🔴 **the densest case in the set (8 boundaries), and the only two-actor walk.** the hazard lives in
the *handoff* rather than in either actor's own path, so no single-side case contains it.

## 🔴 .what the seam exposes that no side does

each of the three sides assumes a precondition the other side is responsible for:

| side | its unstated assumption |
|------|------------------------|
| **c2** (upgrade) | that a consumer who makes the code compile has finished the upgrade |
| **c6** (ci iam) | that the wish **declares** the two new properties, so the writes actually fire |
| **c7** (teardown) | that the versioned fixture already exists |

⇒ **join them and the assumptions collide.** the cheapest upgrade a consumer can make — four `null`s,
enough to compile — declares no value, so **no write is ever issued**, so **c6's iam gap never
fires**. ci goes green. the grants are still absent. and the failure now waits for whichever future PR
first declares a real value — a one-line diff, months later, with a red pipeline and no obvious cause.

**the seam converts a loud, immediate, correctly-attributed failure into a quiet deferred one.** that
is the defect, and it is invisible from either end.

## 🟢 .the nested shape NARROWS this seam to ONE grant

under **F10** the two properties are **nested fields**, so vlad's minimal upgrade cannot skip them —
the compiler demands a value on every bucket he declares, and `getOneS3Bucket` then reads both on
every plan. **three of the four new grants fire at week 1:**

| the new grant | when it first fires under the nested shape | why |
|---|---|---|
| `s3:GetBucketVersioning` | 🟢 **week 1, at plan** | the read is unconditional — A-8 |
| `s3:GetBucketPublicAccessBlock` | 🟢 **week 1, at plan** | the read is unconditional — A-8 |
| `s3:PutBucketPublicAccessBlock` | 🟢 **week 1, at apply** | `access: { public: 'blocked' }` expands to all four true (F15), so an unblocked bucket plans a real UPDATE — c2 `[t3]` |
| 🔴 `s3:PutBucketVersioning` | ⛔ **week 6** | `versions: false` issues no write, and no default would |

⇒ 🔴 **the seam survives on exactly one grant, and it is the one whose write is a ONE-WAY DOOR.**
that is the worst grant to defer: the week-6 PR that first declares `versions: { status: 'enabled',
… }` is also the PR that makes the property unremovable (**I-1**, `case=3`), so a red pipeline lands
on a diff the author cannot cleanly revert.

### 🔴 F16 did NOT close this seam — and the reason bounds F16's whole win

F16's forced key makes *"versions on, expiry forgotten"* unrepresentable. this seam is *"versions
**off**"*, and `false` is a first-class, fully legal, entirely reasonable value.

⇒ **a forced key forces a CHOICE; it cannot force a NON-DEFAULT.** so every property whose safe
value is *off* keeps its upgrade seam whatever shape the type takes. that is the bound on F16's win,
and it is recorded here rather than in the fulcrum because **this is the one case that measures it.**

🟡 and F16 moved the seam's edge in the *helpful* direction by a hair: the week-6 diff is no longer
one flipped key but a `false` replaced by a two-key object — a **larger** diff, which reads as a more
deliberate act and therefore a slightly better attribution cue. ⇒ a real gain, and far too small to
retire the residue.

### 🟢 what this does to Q-13's accepted risk

Q-13 asked the wisher to accept that *"for **one** consumer population … a sharp critipath's `fast`
and `loud` fail-safes are **unreachable**, so the failure defers past the upgrade PR and arrives
**misattributed**."*

| the residue's two halves | under the nested shape |
|---|---|
| the failure **defers** past the upgrade PR | 🟢 **much narrower.** three of four grants are proven at week 1; only the versions put defers |
| it arrives **misattributed** | ⚠️ **all but unchanged.** the week-6 diff is a token swapped for a two-key object — marginally more deliberate than one flipped key, and still a weak attribution cue |

⇒ **the acceptance still holds and its subject shrank.** re-scope it at `2.1.criteria` to the one
deferred grant rather than to the whole new subsystem.

### ⚠️ what does NOT change

the case's **mechanism** stands: a seam between *"the code compiles"* and *"the writes fire"* is
real, and one write sits on the far side of it. c10 keeps its place among the critipaths — and it is
now a **sharper** case, because the residue is one named grant rather than a diffuse population.

🟢 **and the security half of this state is closed.** the same undeclared posture F13 named as a
silent exposure is now carried by the type: there is no *"declare no block"* path, so the only route
to a public bucket is a typed-out opt-out a reviewer can see (c2 `[t5]`).

### 🔴 what the latency measure proves — and the three-round argument it RETIRES

⚠️ **this section argued, across three rounds, that a red `fast` clause is not the same as an

⇒ 🔴 **the lesson is worth more than the argument was.** three rounds were spent on *"is a red clause

it survives every review that only checks the reasoning.*

note were the **only** remedy for the **whole** population. that claim was too wide, and peer review
