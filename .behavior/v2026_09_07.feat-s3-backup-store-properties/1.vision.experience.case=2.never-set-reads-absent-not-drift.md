# case=2 — never-set reads absent, not drift

**feel** sharp → happy · **care** critipath · **actor** `consumer` · **cells** 4, 10, 16

⚠️ the feel is **two-beat**, not flat happy: a forced wish edit at the upgrade (sharp, and it hits
every extant consumer), then the KEEP (happy).

**this is the permadrift trap.** three properties, three *different* aws absent-reads, one required
outcome: `null`, and a KEEP that must hold on all three. 🔴 **the fourth property is the exception
that proves the rule** — `access.public` reads back all-false and plans a real UPDATE, because
F11 made `null` mean *secure*. three non-events and one honest change.

## .narrative

marina runs the mail store. she upgraded `declastruct-aws` for an unrelated reason.

### ⚠️ the upgrade is NOT silent — she must edit her wish before it compiles

`rule.forbid.undefined-inputs` bars an optional field (**A-1**), so every new property is
**required-nullable**, and a `1.11.0` wish **does not typecheck** against `1.12.0`.

this repo's own fixture is the proof. `resources.acceptance.ts:823-836` declares `mailStore`
**today** as exactly:

```ts
lifecycle: { transitions: [ …GLACIER_IR, …DEEP_ARCHIVE ], expireAfterDays: null },
```

— no `access`, and a **flat** lifecycle where there will be a nested one. **the package's own
acceptance fixture is a file this change must edit**, which settles the question: no extant
consumer's wish survives the upgrade untouched.

🔴 **and F16 widened that from an ADDITION to a RESHAPE.** the flat shape would have let marina keep
her two extant lifecycle lines and add four; under F16 her `transitions` and `expireAfterDays`
**move** into an `objects` sub-object, so even a consumer who wants none of this wish's properties
must rewrite the object. ⇒ **the break now reaches every `lifecycle` declaration in existence**, which
is the largest single cost F16 carries and is recorded against **A-1** and **Q-12**.

so the real experience has two beats, and the first one is **sharp**:

1. she upgrades → **the build breaks** until she reshapes every `lifecycle` she declares.
2. she writes the obvious minimum → **three properties read KEEP, and the block plans one UPDATE**
   that blocks public access. that beat is the happy one, and it is not silent.

⇒ the wish edit is **forced and visible**, so a consumer arrives at beat 2 deliberately rather than
unaware. that is the pit of success `rule.forbid.undefined-inputs` is meant to build (the same
mechanism invariant **I-3** relies on), bought at the price of a break on an additive wish.

⚠️ **the new fields are NOT additive.** they **break the source** of every extant consumer, which is
a release-note and semver question the wisher should see. → recorded against **A-1**.

```ts
// beat 2 — after marina reshapes what the compiler demanded
const mailStore = DeclaredAwsS3Bucket.as({
  name: 'ehmpathy-mail-inbound-demo',
  access: { public: 'blocked' },                    // 🔴 the token, never null (F15)
  lifecycle: {
    // ⚠️ RE-HOMED — both keys moved here wholesale from the flat shape (F16)
    objects: {
      expire: null,                                 // was `expireAfterDays`
      transitions: [
        { afterDays: 30, class: 'GLACIER_IR' },
        { afterDays: 180, class: 'DEEP_ARCHIVE' },
      ],
    },
    versions: false,                                // never configured — reads absent, not drift
    multiparts: { expire: null },                   // new, and deliberately unset
  },
  tags: { managedBy: 'declastruct', purpose: 'acceptance-test' },
});
```

🟢 **note what `versions: false` buys her that `versions: null` did not.** the flat shape said
*unset*; the token says **off**, and a token that names a state is one a reader of the fixture will
not casually overwrite — which matters here precisely because `mailStore` is the one bucket in the
suite that receives objects (`case=7`).

she runs plan, expects no change, and gets **one**:

```
$ npx declastruct plan --wish resources.ts --into .temp/plan.json

   ├─ ✔ done in 0.38s
   └─ decision [UPDATE]
      - Remote
      + Desired

        Object {
          "access": Object {
            "public": Object {
              "acls": Object {
      -         "block": false,
      -         "ignore": false,
      +         "block": true,
      +         "ignore": true,
              },
              "policies": Object {
      -         "block": false,
      -         "restrict": false,
      +         "block": true,
      +         "restrict": true,
              },
            },
          },
        }
```

🔴 **three properties KEEP and one plans an UPDATE, and that is the design.** `versions` and the two
lifecycle fields read absent → `null` → no change. **`access: { public: 'blocked' }` expands to all
four true (F15)**, so an unblocked mail store is a real divergence and the plan says so.

🟢 **this case is the sharpest demo of F15's own criterion.** under F11 the line read
`access: { public: null }` — *"no value set"* on the page, four `true`s in the plan. **the diff
above would astonish a reader who had not read F11.** with the token, the line says what the diff
does, and the surprise is gone with no change to the behavior.

## 🔴 .the upgrade is NOT read-only, and every consumer feels it once

| | |
|---|---|
| **who** | every extant consumer with a bucket that has no public-access block |
| **what** | one `PutPublicAccessBlock` per bucket, on the first apply after upgrade |
| **why it is right** | `rule.require.safe-by-default` — the path of least effort must land on the safe outcome, and the one-token `'blocked'` IS that path |
| **why it is loud** | it is a plan line with a four-boolean diff, read before any write. it cannot happen unnoticed |

⚠️ **F11's own honest counter names this cost and the council took it knowingly**: *"(b) plans an
UPDATE on every extant unblocked bucket in every consumer's account the first time they upgrade."*

🔴 **and marina can opt out — deliberately, and in the open.** a bucket that must stay public-capable
declares the four booleans explicitly:

```ts
access: {
  public: {
    acls:     { block: true, ignore: true },
    policies: { block: true, restrict: false },   // ← the one exception, named
  },
},
```

🟡 **the 2×2 sharpens this**: under the flat shape a spread plus one override
(`{ ...blocked, restrictBuckets: false }`) hid the exception inside a spread. the nest refuses that
shortcut — a partial override needs a nested spread, so the cheaper path is to type both groups out,
and **the exception lands on its own line where a reviewer reads it.**

⇒ **that asymmetry IS the pit of success**: the secure posture costs `null`, the public one costs a
typed-out exception a reviewer can see in the diff.

⚠️ **this also raises A-8 from a read cost to a WRITE cost.** the upgrade needs
`s3:PutBucketPublicAccessBlock` at apply, not merely the two new `Get` grants at plan → `case=10`.

what she never sees is that **four** wholly different aws behaviours, across three properties, each
had to read as the one canonical absent value **its own property declares** for that plan to be
**honest** — three so their KEEP is real, and the fourth so the one UPDATE is real too:

| property | what aws actually returned | naive read | required read |
|----------|---------------------------|------------|---------------|
| lifecycle.versions | `{}` — an **empty body**, no `Status` key at all | `undefined` | 🔴 **`false`** — the off-token, never `null` (**F16**) |
| access.public (a) | a **thrown absent-signal error** — ⚠️ name UNVERIFIED, see below | a thrown error | 🔴 `s3BucketAccessPublicUnblocked` |
| access.public (b) | 🔴 a **200 with a present-but-empty `{}`** — all four booleans undefined | a partial object, or a defaulted one | 🔴 `s3BucketAccessPublicUnblocked` |
| lifecycle.multiparts.expire | a lifecycle rule with the **sub-object omitted** | `undefined` | `null` |

🔴 **F16 broke a claim an earlier draft made here, and the break is the lesson.** that draft read
*"all four had to read as the same `null`"* — a tidy sentence, and now false. under F16 the four
behaviours canonicalize to **three different written forms**: `false` for `versions`, the all-false
const for `access.public`, `null` for `multiparts.expire`. ⇒ **"absent" is a per-property contract,
never a repo-wide constant** — which is exactly what `case=4` grades and what an implementer who
carries one global absent-value into the cast will get wrong three ways.

### 🔴 why the block's absent read is an explicit ALL-FALSE const, never `null`

F11 makes `null` mean *the secure default*, and `omitReadonlyDeep` re-instantiates **both** operands
through the constructor before the compare. so a cast that returned `null` for an absent block would
be canonicalized to all-four-true on the **remote** side too — **equal to desired, KEEP, on a bucket
that is wide open.** a silent false KEEP on the security posture, which is strictly worse than the
permadrift this case is named for.

⇒ the cast must return the **explicit insecure value**, exactly as the peer does:
`ec2InstanceMetadataOptionsAwsImplicit` exists for this reason, and its doc says so — *"the cast
reads such a template back as these values (NOT null) so it does NOT collapse to the secure default
— a pre-feature template plans a change instead of a false KEEP that masks an insecure box."*

⚠️ **so `null` is asymmetric across the two operands**, and that is deliberate: it is a legal *wish*
value and never a legal *read* value for this one property. of the other three, the two `expire`
fields read `null` on both sides, and **`versions` reads `false` on both** — F16 removed `null` from
that field's type altogether, so the asymmetry cannot arise there by construction.

🔴 **rows (a) and (b) are the same property and the same sense, in two different wire shapes** —
and an earlier draft named only (a). `PublicAccessBlockConfiguration` types all four booleans as
independently optional (`models_0.d.ts:10155-10182`), so the empty body is representable, and the
repo already treats it as real for a structurally identical sub-block: the peer
`asDeclaredAwsEc2InstanceMetadataOptions.ts` carries an `isWhollyAbsent` predicate whose sole job is
to fold *"key omitted"* and *"present-but-empty `{}`"* into one absent read, because a per-sub-field
fallback on the empty shape would *"read back fully SECURE and false-KEEP"* a resource that is not.

⚠️ **the general lesson: a decomposition is total over MEANINGS, not over ENCODINGS.** the grid's
`absent` was one cell per property and looked complete, because at the level of *sense* it was.

### 🔴 the absent-signal for `access.public` is NOT yet verified — and that is a blocker

the wish names the error `NoSuchPublicAccessBlockConfiguration` (`0.wish.md:38`), and this vision
repeated it. **it has no grounding.** three places were checked:

| source | result |
|--------|--------|
| `@aws-sdk/client-s3@3.943.0` — all 207 lines of `models/errors.d.ts` read | models **14** error classes; this is not one of them |
| aws's `GetPublicAccessBlock` API reference | documents **no errors at all** — no error section, no code, no status |

⚠️ **the sdk's silence is weaker evidence than it looks.** `NoSuchLifecycleConfiguration` is **also
absent** from those 14 — and this repo matches that name by string today, successfully
(`getBucketLifecycle.ts:51`). so aws routinely emits error codes the js sdk never declares, and
match-by-`error.name` is the right pattern *because* of that. the absence confirms the **pattern**
and is silent on **this string**.

so the name traces to the wish's advisory prose and stops there. it may well be right — it is the
shape aws uses elsewhere — but **"it fits the pattern" is precisely the argument this repo has
already been burned by twice.**

`rule.forbid.plan-fail-on-apply-guided-prereq` names this exact failure and grades it a **blocker**:

> *"the repeat root cause — verify the aws signal, do not assume it … this defect hit TWICE, both
> times from the SAME mistake: an ASSUMPTION of which aws error signals 'prereq off' instead of a
> check against the live api."*
>
> *"an off-signal detector built on an UNVERIFIED aws error shape = blocker"*

and the consequence here is the one that rule exists to prevent: if the name is wrong, the `catch`
never fires, the `get` rethrows, and **the whole plan aborts** — for every consumer, on a bucket
that merely never had the block configured. the rule's own past incident is the precedent: the
assumed name was `DataUnavailableException`; the live api threw `AccessDeniedException` with a
message-signal instead.

**the obligation, carried forward to execution:** call `GetPublicAccessBlock` against a real bucket
with no block configured, and read the `name` and `$metadata.httpStatusCode` off the thrown error.
match on what it actually emits. **do not implement the detector from this vision's string.**

⚠️ the `[t1]` step below is written against the name as a *placeholder*, not as a settled fact.

get any one of them wrong and marina's plan reads `UPDATE` forever, on a bucket she never touched,
for a property she never asked for. the apply would "succeed", write no new value, and the next
plan would say UPDATE again. **that is the permadrift** — and it would land on every extant
consumer of the package, not just on new backup stores.

## .the `[tn]` timeline

the narrative shows a non-event. the timeline names the three distinct mechanisms behind it, and
adds the one claim prose cannot make: that the 404 is **caught**, not degraded from a real error.

### ⚠️ each degrade belongs to its COMMUNICATOR, not to the cast

a first pass placed all three normalizations in `castIntoDeclaredAwsS3Bucket`. that is the wrong
layer, and it is wrong in a way that would silently defeat `[t1]`: **the cast's input is a plain
structural type, never an sdk response** (`castIntoDeclaredAwsS3Bucket.ts:17-24` — `{ name,
lifecycle: {…} | null, tags }`). an sdk error never reaches it; the error propagates out of the
communicator and aborts the whole plan first, so a `catch` written in the cast would never fire.

the extant precedent settles both the shape and the place: `getBucketLifecycle.ts:50-57` matches
`error.name === 'NoSuchLifecycleConfiguration'` and returns `null` **inside the communicator**, and
its own doc comment says so — *"the sdk gives no dedicated class, so match on the error name **at
this boundary**"*. so the three degrades below are owed to three different files.

```
given  [case2] a bucket that exists and has NEVER had any of the four properties set
  and  a wish that declares `versions: false` and both `expire` fields null

  when [t0] the `getBucketVersioning` communicator reads `GetBucketVersioning`
  then  the response body carries no `Status` key
   and  🔴 THAT COMMUNICATOR yields `versions: false` — never `undefined`, never
        `null`, never 'Disabled'  (aws models no 'Disabled' state — see the
        groundwork; and F16 removed `null` from the field's type, so the off
        state has exactly ONE written form on BOTH operands)
   and  the cast receives a value already normalized to the token; it adds no degrade

  when [t1] the `getPublicAccessBlock` communicator reads `GetPublicAccessBlock`
        and aws signals absence by a THROWN error
  then  THAT COMMUNICATOR catches THAT error and yields
        🔴 `s3BucketAccessPublicUnblocked` — all four booleans FALSE, explicit
   and  it does NOT yield `null` — null is canonicalized to all-four-TRUE on
        BOTH operands, so a null read would false-KEEP an unblocked bucket
        (never the cast — an sdk error does not reach the cast; see the note above)
        (⚠️ name UNVERIFIED — the wish says NoSuchPublicAccessBlockConfiguration;
         execution MUST read the live error's name before it writes the detector)
   and  an `AccessDenied` or any other error is NOT caught — it propagates
        (rule.forbid.failhide: only the one known absent-signal degrades)
   and  the detector matches the signal aws ACTUALLY emits, never an assumed name
        (rule.forbid.plan-fail-on-apply-guided-prereq — blocker)

  when [t1b] the SAME read returns 200 with a PRESENT-BUT-EMPTY body
        ({ PublicAccessBlockConfiguration: {} } — all four booleans undefined)
  then  THAT COMMUNICATOR yields `s3BucketAccessPublicUnblocked` — the SAME
        read as [t1]: two wire shapes, one sense
   and  it does NOT throw (an absent block is not a defect)
   and  it does NOT fall through to a per-sub-field default
   and  ⚠️ a wholly-absent block IS an exposure aws reports by omission, so the
        all-false read states what is true; a `true` default would false-KEEP it

  when [t2] the extant `getBucketLifecycle` communicator reads the lifecycle
  then  the declastruct-owned rule carries neither `AbortIncompleteMultipartUpload`
        nor `NoncurrentVersionExpiration`
   and  null is yielded for `multiparts.expire` — never 0
   and  🔴 the `NoncurrentVersionExpiration` omission has NO field to land in at all:
        under F16 that expiry lives inside the `versions` object, and [t0] already
        read `versions: false`. ⇒ the cast MUST NOT synthesize a `versions` object
        to hold it — an omitted noncurrent expiry on an off bucket is not an absent
        value, it is an ABSENT SLOT  (F16's forced key, read in reverse)
   and  ⚠️ this degrade is an OMITTED SUB-OBJECT on a rule that was returned, not a
        thrown error, so it is read where the rule is shaped — unlike [t0] and [t1]

  when [t2b] the SAME read returns a rule that DOES carry NoncurrentVersionExpiration
        while [t0] read `versions: false`   (aws permits this — a stale rule on a
        bucket whose versioning was later suspended and whose versions aged out)
  then  🔴 the two reads CONFLICT, and the cast cannot represent the pair
   and  it fails loud rather than drop the expiry or invent a `versions` object
        (rule.forbid.failhide — F16's forced key makes this pair unrepresentable,
         so it MUST be surfaced; execution owes the exact message)

  when [t3] plan runs
  then  `versions` and the two `expire` fields do NOT appear in the diff
   and  🔴 `access.public` DOES — remote all-false vs desired all-true
   and  the decision is UPDATE, and it names the four booleans

  when [t4] apply runs, then plan runs again
  then  ONE PutPublicAccessBlock was issued, for this bucket
   and  the decision is now KEEP
   and  a third plan is still KEEP  (a permadrift would surface here)

  when [t5] a consumer who WANTS the bucket public-capable types both groups
        out explicitly, with policies.restrict: false
  then  the plan reads KEEP against their unblocked bucket
   and  no PutPublicAccessBlock is issued
   and  🔴 the opt-out is VISIBLE in their wish and in code review, where the
        secure posture costs `null` — rule.require.safe-by-default, rung 2
```

🔴 **`[t3]`–`[t5]` are the case's centre now.** `[t0]`–`[t2]` describe reads that behave correctly;
these three describe the one property whose correct read produces a **change**, and the one line that
opts out of it.

⚠️ **`[t5]` is deliberately an observable `then`, not prose** — a criterion at `2.1.criteria` asserts
that the explicit opt-out converges, which is the only proof that the secure default is a *default*
rather than a mandate.

- **`[t1]`'s "never the cast"** — the narrative shows a `null`; it cannot show WHICH layer produced

- **`[t2]`'s "never 0"** — `0` is a *legal* aws value for `DaysAfterInitiation`, and a naive

## 🔴 .does the edge fail safe?

graded against the five clauses — **fast · loud · teaches the fix · holds the limit · drops no data
silently**.

### 🔴 first, the split — an EDGE is not a HAZARD

the five clauses grade **what the actor meets at the edge**. they do not grade **what happens if we
implement the handler wrongly** — and that distinction is not a convenience:

> 🔴 **if the clauses graded implementation defects, every case in every vision would be red on all
> five**, since one can always posit a handler written wrong. the rubric would grade no case at all.

so c2 carries **one edge** and **two hazards**, and they take different instruments:

| | what it is | the right question |
|---|---|---|
| **edge A** — the forced wish edit | what the actor **feels** at the upgrade | ✅ **does it fail safe?** — the five clauses |
| **hazard B** — a wrong degrade → permadrift | a defect in **our** implementation | 🔴 **what gate catches it, and where?** |
| **hazard C** — a `catch` wide enough to swallow `AccessDenied` | a defect in **our** implementation | 🔴 same |

⇒ **and the hazards already have their handling shown: it is `[t1]` and `[t2]` themselves.** `[t1]`'s
two `and` clauses ARE the guard against hazard C — *"an `AccessDenied` or any other error is NOT
caught — it propagates"*. hazard C is what the demo **prevents**, never an edge the demo leaves open.

### edge A — the forced wish edit (the sharp beat, `A-1`)

| # | clause | grade |
|---|--------|-------|
| 1 | **fast** | ✅ **the earliest point that exists** — `tsc`, before any plan, any aws call, any write |
| 2 | **loud** | ✅ the compiler names the file, the line, and each absent property |
| 3 | **teaches the fix** | ✅ on a **bounded** claim: the fix is *"supply a value for this property"*, and `tsc` teaches exactly that, at the edge, by file and line. **which** value to supply is the *choice*, a separate obligation — the residual below |
| 4 | **holds the limit** | ✅ the type IS the limit; there is no path that compiles past it |
| 5 | **drops no data silently** | ✅ no write is issued — the build never ran |

#### 🔴 a FIX and a CHOICE are not the same obligation

clause 3 asks whether the edge teaches **the fix**. the fix for a compile break is *supply a value*,
and `tsc` names the file, the line, and each absent property. ⇒ **taught, at the edge, in full.**

🔴 **a compiler that taught the CHOICE would be a REGRESSION.** to teach a value is to have a
default; a default for `lifecycle.versions.expire` is the silent cost leak the wish exists to remove
(**F5**, demoed at **c11**). so the clause is not merely satisfied — **the un-taught choice is the
feature.**

🟢 **and F16 sharpened clause 3 on exactly this field.** under the flat shape, `tsc` named
`expireNoncurrentVersionsAfterDays` as one more absent property among four, with no clue that it was
only meaningful once versioning was on. under F16 the compiler will not name it at all until the
actor has written `versions: { … }` — and **the moment they do, it is the one remaining absent key
inside a two-key object.** ⇒ the fix is taught with the *context* that makes the choice answerable,
which is a strictly better teach than the flat shape could give.

> **the guarantee is about the ASK, never about the ANSWER.**

#### the residual — what the moment of failure does not settle

a required-nullable field can force a decision to be **MADE** and cannot force it to be **RIGHT**:

| what the moment of failure DOES teach | what it does NOT |
|---|---|
| ✅ **which** property is absent — `tsc` names the field | ⛔ **which value** to give it |
| ✅ that the fix is a source edit, not a config change | ⛔ that `null` is **not** universally safe — right for `mailStore`, **wrong** for a backup store |
| — | ⛔ that a **second**, runtime break (`A-8`) is still owed once the compile passes |

⇒ **so the compile error teaches the fix precisely, and leaves a choice that is wrong half the time —
and the wrong half is the one this wish exists to serve** (a backup store, which wants a number). the
carriers for the *choice* are the field-doc `.note` at the declaration (rung 3) and the release note
(rung 4 — **Q-12**).

🔴 **and the third row is the one to carry forward** — `A-8`'s runtime break is invisible at this
edge by nature, which is why the seam earns **c10** rather than a note here.

🔴 **it is accepted rather than closed because no better rung is reachable.** `tsc` cannot know a
bucket's purpose, so rung 1 (*make it impossible*) and rung 2 (*make it hard*) have no expression
here: there is no wrong **value** to forbid, only a value that is wrong **for this bucket**.
⇒ ***a compile error can enforce that a decision is MADE; it cannot enforce that the decision is
RIGHT — and where the right answer depends on an intent the type cannot see, rung 3 is the highest
rung that exists.***

⚠️ **note this cuts the opposite way from [c11](1.vision.experience.case=11.typed-out-null-keeps-all-versions.md), and both are true.** c11 shows the
same forced choice as the wish's central pit-of-success win; this row shows its limit. **the type's
guarantee is about the ASK, never about the ANSWER** — which is exactly why c11's fail-safe had to be
framed as a check on the value's *provenance* rather than on the value.

🔴 **but clause 1 holds for only HALF of the upgrade break.** `A-1` fails at compile; **`A-8`** — the
two new unconditional `Get*` grants — fails at **runtime**, in the consumer's pipeline, on **every**
bucket. so a consumer who satisfies the compiler is still broken, and the compile break's speed
**hides** that, because it implies the upgrade cost was paid in full. ⇒ that seam is **c10**, and
this row is why it earns its own case rather than a note here.

### 🔴 the two hazards — graded by WHERE THE GATE IS, not by the clauses

both are defects in **our** implementation, so the question is what catches them and how early:

| hazard | if we get it wrong | the gate | where it fires |
|--------|--------------------|----------|----------------|
| **B** — a wrong degrade | a permadrift: UPDATE forever on a property the consumer never touched | ✅ **the acceptance suite's `then('all resources show KEEP after apply')`** — it filters every change for `action !== 'KEEP'` and fails the **whole suite** on any survivor | **our ci, first run, before ship** |
| 🔴 **C** — a `catch` wide enough to swallow `AccessDenied` | an absent read-grant becomes a phantom `null`, then a phantom **CREATE**, which **writes** — it can put a block onto a bucket whose real block the reader was merely not permitted to see | ⛔ **no extant gate.** our own ci roles hold the read grants, so the swallow never fires there; only a least-privilege consumer reaches it | 🔴 **nowhere, at our grain** |

🔴 **hazard B's gate is the strongest fact in this case, and it is inherited rather than proposed.**
a permadrift on any of the four properties fails our ci on the first run, loudly, before ship —
which is the same argument c10's carrier 1 makes, and it generalizes: **a gate in a fixture beats a
caveat in a document, because the fixture runs.** the difference is that c10 had to *propose* its
fixture; c2 **inherits one that already runs on every apply**.

🔴 **hazard C has no gate, and that is exactly why `A-5` is graded a blocker.** its sole defence is
the **narrowness of the detector** — which is why `[t1]` spends two `and` clauses on a distinction
prose renders invisible (both spellings produce the same happy narrative), and why an **unverified**
error name is not merely an un-implemented detector: it is the pressure that widens a `catch` until
hazard C becomes reachable.
