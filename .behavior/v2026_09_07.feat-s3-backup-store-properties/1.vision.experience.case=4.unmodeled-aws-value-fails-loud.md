## .the three read surfaces

one invariant, three places it must hold. all three are new attack surface this wish opens:

| surface | the unmodeled value | why the naive read is wrong |
|---------|---------------------|-----------------------------|
| **`versions`** | a `Status` outside `{'Enabled','Suspended'}` | a bare cast types a string we never validated. today aws models only two, but the enum is aws's to grow |
| **noncurrent expiry** | ~~`NewerNoncurrentVersions`~~ — **NOW MODELED as the `keep` count axis (F18, ruled 2026-09-11)**. verified present in the sdk (`NoncurrentVersionExpiration`, models_0.d.ts:6548-6561). found by the groundwork read; the wish did not name it, F18 then modeled it |
| **public-access block** | a **fifth** boolean aws adds later | `PublicAccessBlockConfiguration` is aws's to grow, exactly as the `Status` enum is. a key we do not model is a posture we cannot represent |

🔴 **the third row was narrowed by the F9 verdict, and the narrowing is the load-bearing part.**
it used to read *"a fifth boolean, **or one of the four absent**"* — one row holding two different
signals under one obligation. the ruling splits them, and only the first still throws:

| the block aws returns | it means | the read |
|---|---|---|
| a key we do not model | a posture we cannot represent | ⛔ **throws** — this row, and it is the c4 invariant |
| a **partially** populated block | a shape aws does not emit | 🟢 **falls back per-sub-field to `false`** — F9 + its 2026-09-13 sub-call |
| a present-but-**empty** `{}`, or a 404 | no block configured | 🟢 **reads absent**, exactly as case=2 does |

🟢 **the last two rows now agree in DIRECTION**, and that is the point of the sub-call: each resolves
an unknown **remote** toward the unblocked read, so neither can report an exposed bucket as blocked.

### 🟢 the third row is RULED — it falls back, it does not throw (fulcrum F9)

**ruled 2026-09-09: the council OVERRULED the best-guess.** an earlier pass had `[t2]` throw on any
absent sub-field. it now **falls back per-sub-field**, in symmetry with the closest peer in this
package — `asDeclaredAwsEc2InstanceMetadataOptions.ts:45-57`.

⇒ **the fork was throw-versus-fall-back, and the fall-back leg won. that half is untouched.** what
the sub-call below settles is the *direction* of the fallback, which the verdict did not name.

### 🔴 the sub-call — the fallback resolves toward UNBLOCKED, not toward blocked (2026-09-13)

**the original render fell back to `true`**, on F11's ground: the cheapest way to write the field
means all four blocked, so `true` is a value this package already made canonical rather than an
invented one. **that argument is sound about the DESIRED side and was applied to the REMOTE side,
where it inverts.**

🔴 **run it.** a bucket whose `RestrictPublicBuckets` is genuinely `false` on aws, returned in a
partial:

```
remote:   { BlockPublicAcls: true, IgnorePublicAcls: true, BlockPublicPolicy: true }
                                                    ← RestrictPublicBuckets omitted
read:     { acls: { block: true, ignore: true },
            policies: { block: true, restrict: true } }   ← the secure fallback
desired:  the same
⇒ KEEP.   RestrictPublicBuckets stays false on aws. silently. forever.
```

🟡 **the 2×2 does not close this door and was never meant to** — a partial arrives from aws's wire,
where the four are flat. the factor governs **our** contract; the cast still has to decide what an
omitted wire field reads as, and that decision is I-8's.

⇒ **that is the exact false-KEEP `[t2b]` exists to prevent**, entered through the partial door rather
than the empty-`{}` door. one fallback direction produced both a guard and the hole beside it.

**the two sides of a plan default in OPPOSITE directions, and both serve safety:**

| side | an unknown resolves to | why |
|---|---|---|
| **desired** — what a consumer declares | 🟢 **secure** | `'blocked'` costs one token; the exposed posture costs four booleans typed out (F11, F15) |
| **remote** — what we read off aws | 🔴 **insecure** | a plan writes desired over remote. read unknown as *secure* → KEEP, no write is issued. read unknown as *insecure* → UPDATE, the block gets written |

🟢 **the peer states this explicitly, and the earlier render read only half of it.**
`asDeclaredAwsEc2InstanceMetadataOptions.ts:27-30` — *"read it back as that honest insecure default so
a pre-feature template plans a change … instead of a false KEEP that masks an insecure box."* its
secure sub-field fallback is a **total-function guard for a shape it proves unreachable**, never a
statement that unknown-remote means secure.

⚠️ **and our unreachability is weaker than the peer's.** theirs is grounded in aws behaviour; ours is
**A-3**, an unverified assumption that needs a live call. ⇒ **an unblocked fallback is correct under
BOTH branches of A-3**; a blocked one is correct only if A-3 holds. the sub-call removes A-3 from the
safety argument entirely.

🔴 **the cost asymmetry is the whole argument, and it is the same one that settled `[t2b]`:**

| the fallback is wrong and the bucket is… | `false` (taken) | `true` (prior) |
|---|---|---|
| actually secure | a redundant idempotent `Put` — harmless | no-op |
| actually exposed | 🟢 the block gets written | 🔴 **silent exposure, KEEP forever** |

⚠️ **`rule.forbid.failhide` is scoped, never waived.** the fallback covers one shape aws does not
emit. the case's other two surfaces — an unknown `Status`, an unmodeled `NewerNoncurrentVersions` —
still throw, and a genuinely unknown value anywhere else still throws.

⇒ the cast owes a **`.note`** that states both the verdict and this sub-call, and cites F9. the
objection F9 overrules is real, and a future reader will re-raise it against a bare fallback with no
record beside it — **and a reader who knows only F11 will re-raise the `true` fallback specifically**,
since its ground is genuine and its scope is not.

## .the `[tn]` timeline

the narrative shows one surface. the timeline holds all three to the same rule — **be honest about
what aws actually sent** — and pins the two
things that separate a real guard from a decorative one.

```
given  [case4] a bucket whose live config carries a value outside our model

  when [t0] `GetBucketVersioning` returns Status='SomeFutureState'
  then  the COMMUNICATOR passes the raw string through — it does NOT degrade it
   and  the CAST throws, via a withAssure type-check
        (`castIntoDeclaredAwsS3Bucket.ts:36` is this exact shape, already live:
         `class: isDeclaredAwsS3StorageClass.assure(transition.class)`, over an
         input field typed as a bare `string`)
   and  the error names the field, the rejected value, and the modeled set
   and  the value is NOT cast through `as` (rule.forbid.as-cast)

  when [t1] the lifecycle read finds NewerNoncurrentVersions set
  then  the read maps it to the `keep` count axis of the VersionExpiry union (F18)
   and  the cast produces `expire: { after: ..., keep: N }` — a modeled value, not a throw
   note  F18 (ruled 2026-09-11) models this field; the pre-F18 throw is retired

  when [t2] `GetPublicAccessBlock` returns a PARTIALLY populated config
            (one boolean present, another absent)
  then  the read FALLS BACK per-sub-field to `false` — the UNBLOCKED value,
        so the plan reads UPDATE and the apply WRITES the real block
        (F9, ruled 2026-09-09; its direction sub-call ruled 2026-09-13)
   and  it does NOT fall back to `true` — a secure fallback on the REMOTE
        side reads an exposed bucket back as blocked and KEEPs it forever
   and  it does NOT throw — a partial block is a shape aws does not emit,
        so the fallback is a total-function guard, not a failhide
   and  the cast carries a `.note` that states both and cites F9

  when [t2b] `GetPublicAccessBlock` returns a present-but-EMPTY `{}`
             (every one of the four booleans absent)
  then  the read takes the SAME path as the 404 of [case2] — no block
        posture was reported, so it reads absent
   and  [t2] and [t2b] agree in DIRECTION — each resolves an unknown
        REMOTE toward the unblocked read, so neither can false-KEEP an
        exposed bucket (the peer's `isWhollyAbsent` proof, F9 defect 30)

  when [t3] the UNMODELED-value reads [t0] and [t1] run at PLAN time
  then  each fails the plan outright — it is NOT degraded to null and NOT
        swallowed (rule.forbid.failhide)
   and  each is distinguishable from the legal-absent reads of case=2
        (an absent Status is null; an UNKNOWN Status throws)
   and  [t2] and [t2b] are NOT in this set — neither reads an unmodeled
        value, so neither aborts the plan (F9, ruled)

  when [t4] the modeled set is extended later
  then  the type AND the runtime guard both widen from ONE const array
        (the isDeclaredAwsS3StorageClass precedent — one source of truth)
```

### what the timeline catches that the narrative does not

- **`[t3]`'s second `and`** — this is the sharpest line in the case, and prose cannot hold it. two
  reads look identical from the outside: *"aws sent no versioning Status"* (legal → `null`, case=2)
  and *"aws sent a Status we do not know"* (illegal → throw). one signal, two opposite obligations.

  ⚠️ **the layer split makes this MORE precise, not less.** case=2's degrade lives in the
  **communicator**; this throw lives in the **cast**. so the two obligations sit in different
  files and cannot be fused by one careless `if` — the structure does that much for free. what the
  structure does **not** prevent is the real hazard, which is narrower and easier to write by
  accident: **the communicator degrades too much.** a `Status ?? null`, or a `catch` one clause too
  wide, converts the UNKNOWN value to `null` before the cast is ever reached, and the guard below
  it never runs. the bucket then reads as never-versioned, plans KEEP, and the unmodeled state is
  invisible — the failhide this case exists to prevent, arrived at from one layer up.

  ⇒ so the obligation is two-sided and each side belongs to a named file: the **communicator**
  normalizes **absent only** (no `Status` key → `null`) and passes every present value through
  untouched; the **cast** rejects every present value outside the modeled set.
- **`[t2]` and `[t2b]`** — the narrative treats the public-access block as four booleans that arrive
  together. the sdk types them independently optional, so **two** shapes the narrative cannot show
  are representable on the wire: a *partial* block falls back per-sub-field, a *present-but-empty*
  one reads absent. 🔴 **they take different PATHS and now agree in DIRECTION** — both resolve toward
  the unblocked read. the 2026-09-13 sub-call is what aligned them; before it, `[t2]` fell back to
  `true` and carried the identical false-KEEP `[t2b]` was written to prevent. ⇒ *a guard placed on
  one encoding of `absent` does not cover its siblings — the peer's `isWhollyAbsent` predicate proves
  the empty-`{}` case and says nothing about the partial.*
- **`[t4]`** — the narrative shows a failure. it cannot show the *maintenance* obligation: the
  guard and the type must derive from one array, or the next author widens one and not the other,
  and the guard silently stops matching the type it claims to enforce.

## .why this is a critipath, not a nicety

- **frequency** — low. an unmodeled value needs an out-of-band edit or an aws api change.
- **cost** — **unbounded**. the failure mode is not a bad error message; it is the **silent
  destruction of a consumer's configuration** on the next replace-all put, discovered from a bill.
  no fallback recovers a setting we overwrote without a record.

`freq × cost` with cost → ∞ is a critipath at any frequency above zero — the
`define.experience._.axis=care` rule, applied straight. and the frequency is provably above zero:
`NewerNoncurrentVersions` is a live field in the sdk today, one console click away.
