# 1.vision.yield — the s3 bucket properties a backup store needs

a backup store can state its own **durability** and its own **exposure**. two fields carry it:
**`access.public`** on the bucket, and a **`lifecycle`** that decomposes by *what expires* —
`{ objects, versions, multiparts }` (**F16**).

```ts
access: { public: 'blocked' | { acls: { block, ignore }, policies: { block, restrict } } },
lifecycle: {
  objects:    { expire: IsoDurationInDays | null, transitions: [ … ] },   // ANY bucket
  versions:   false | { status: 'enabled' | 'suspended',
                        expire: VersionExpiry | null },                   // only if versioned
  multiparts: { expire: IsoDurationInDays | null },
} | null,

// versions expire by AGE, by COUNT, or by both — at least one, never neither (F18)
type VersionExpiry = { after: IsoDurationInDays; keep: number | null }
                   | { after: null;             keep: number };
// reads as a sentence:  expire: { after: { days: 30 }, keep: 5 }
```

🔴 **the shape is not four flat fields, and the difference is the point.** `versions.expire` is
**unreachable** unless `versions` is an object with a `status` — so *"versions on, expiry forgotten"*,
the wish's own second failure mode, **cannot be typed**. that is `rule.prefer.prevent-over-correct`
**rung 1** — make it impossible — where a flat `expireNoncurrentVersionsAfterDays` sat at rung 3.

**names**: our declared fields use house words; aws's own symbols keep the api's letters. the split
is **ownership**, and it applies three times:

| ours — renamed | aws's — verbatim |
|---|---|
| `lifecycle.versions`, not the gerund; `status: 'enabled' \| 'suspended'`, lowercase (**F16** sub-call 1) | `Put/GetBucketVersioning`, `s3:GetBucketVersioning`, the wire values `Enabled`/`Suspended` |
| `access: { public }`, its four sub-fields factored into a 2×2 — `acls: { block, ignore }`, `policies: { block, restrict }` (**F14**) | `PublicAccessBlockConfiguration`, `Put/GetPublicAccessBlock`, `s3:*BucketPublicAccessBlock` |
| `lifecycle.{objects,versions,multiparts}.expire` — one verb for one motive (**F16**) | `LifecycleExpiration`, `NoncurrentVersionExpiration`, `AbortIncompleteMultipartUpload` — **two** verbs for it |

⇒ **the path says *public* once** — `access.public.acls.block`. aws says it four times.

⇒ 🔴 **and the second row is a FACTOR, not a rename.** aws ships four flat booleans; their own field
docs each name their complement (*"doesn't affect existing"*, *"doesn't prevent new"*), which
recovers a dense 2×2: `{acls, policies} × {reject new, neutralize extant}`. the factor also repairs
`RestrictPublicBuckets` — a **policy** field with a bucket's name, on its own doc's words — and the
plural disappears with the noun. enruled as `rule.require.decompose-attributes-on-common-nouns` +
`howto.factor-an-attribute-set` (this repo), dispatched to the architect as
`rhachet-roles-ehmpathy#677`.

⇒ 🟡 **and the third row costs a `.note`.** `multiparts.expire` drops aws's word *incomplete*, so the
field owes a note that names `AbortIncompleteMultipartUpload`, states *in-progress parts only*, and
points a **completed** upload at `objects.expire` (**F16** sub-call 3).

## .the outcome world

### a day in the life

vlad opens `ahbode/infrastructure`, declares one object, and gets a backup store that cannot bill
him by surprise:

```ts
const bucket = DeclaredAwsS3Bucket.as({
  name: 'ahbode-camp-git-backup',
  access: { public: 'blocked' },              // 'blocked' = all four true — F15
  lifecycle: {
    objects:    { expire: null, transitions: [] },          // keep every current object
    versions:   { status: 'enabled',
                  expire: { after: { days: 30 },            // on ⇒ expiry is REQUIRED
                            keep: null } },                 // …by age here; a count is the other axis
    multiparts: { expire: { days: 7 } },                    // in-progress parts only
  },
  tags: { managedBy: 'declastruct', purpose: 'git-backup' },
});
```

`plan` → CREATE. `apply`. `plan` → **KEEP**. that KEEP is the deliverable.

⚠️ **the write ORDER inside `setS3Bucket` carries a real obligation.** the version-state put is the
one **irreversible** write in this wish (invariant I-1), so it must run **last**, after every
reversible step has succeeded. the sequence at `setS3Bucket.ts:48-96` becomes: `createBucket` →
lifecycle put → public-access block → tag reconcile → **the version-state put**. it owes a `.note` at
that call site which names I-1, since the order is otherwise indistinguishable from an arbitrary one
and a later refactor would reorder it freely. ⇒ `case=1` `[t1]`.

🔴 **and F16 sharpened that obligation rather than moved it.** `lifecycle.versions` now straddles
**two api calls** — the version-state put writes `status`, the lifecycle put writes `expire` — so the
order splits **one declared field's two halves** rather than two separate fields. a partial apply
leaves it half-written; the extant per-call loud-fail covers it, and the next plan's read shows the
true split state, so it converges (**F16** sub-call 2).

### before / after

| | before (`1.11.0`) | after |
|---|---|---|
| a backup store's durability | not expressible — no versions field | `lifecycle.versions.status` |
| a backup store's exposure | not expressible — no public-access block | `access: { public: 'blocked' }` |
| a dead writer's stranded multipart parts | accrue forever, invisible to `aws s3 ls` | `multiparts.expire` aborts them |
| noncurrent versions | not expressible, so the moment versions existed they would pile up | `versions.expire` — and 🔴 **the type will not let you omit it** once `status` is set |
| the flat lifecycle's two ambiguous names | `expireAfterDays` names no subject — **which** thing expires? | one verb, three subjects: `objects`/`versions`/`multiparts`, each with `.expire` |
| `ahbode/infrastructure#35` | 3 of 8 acceptance criteria unstateable | all 8 stateable |

### the aha

**it is not the fields. it is the second plan.**

the fields are an afternoon. what makes them worth a wish is that each round-trips through an aws
api that canonicalizes, and each has a *different* absent-read — an empty body, a 404, an omitted
sub-object. get one wrong and every extant consumer's plan reads UPDATE forever, on a property they
never declared, and no apply can close it.

🟡 **F16 raised that bar rather than lowered it.** the nest adds **written forms** — a bucket with no
version config can be written `versions: false`, and the canonicalizer must produce exactly that from
an empty `GetBucketVersioning` body. ⇒ *a group key does not merely add a path segment; it adds a
position, and every position on a round-tripped field is a form the canonicalizer owes.*

so the value clicks at `plan` #2, when it says `KEEP` — because that is the moment a consumer can
put the wish in ci and trust that **a non-empty plan means a real change**. the wish says it
outright: *"the ask is not merely add the fields but add them such that a plan → apply → plan
converges to KEEP."*

### what the walk found that a free-list would have missed

**four** items, each off an axis rather than out of memory:

1. **a live defect in shipped code.** the `concurrency / time` axis exposed that
   `setS3Bucket.ts:66-84`'s stability predicate compares `transitions.length` alone. a backup store
   declares **zero** transitions and puts all its content in the two new sub-rules — so the
   predicate matches before the write lands. → case=5, fulcrum F6.
2. **a critipath that exists only for `system:ci`.** ci runs as `ehmpathy-demo-oidc`, whose inline
   policy lacks the two new **write** grants, and the failure signature (green local, red ci) is the
   repo's own documented misdiagnosis hazard. managed `ReadOnlyAccess` covers the reads, so **the
   plan is clean and the apply is what breaks**. → case=6.
3. **an aws field the wish did not name.** `NoncurrentVersionExpiration` carries
   `NewerNoncurrentVersions` beside `NoncurrentDays`. we do not model it; a read that dropped it
   would let the next replace-all put destroy a consumer's console config. → case=4.
4. **that two of the wish's known hazards are ONE hazard.** the **grant grain** axis puts **A-8** and
   **c6** in one table: a role that holds `s3:Get*` and lacks the two `Put*` fails at **apply**; a
   role that lacks the two `Get*` fails at **plan**, on every bucket. same phenomenon, two grains.
   → `dimensions.md` §`F`.

## .the mental model

### how a consumer would describe it to a friend

> *"the bucket declaration finally has the safety switches. versions on, public off, and it cleans
> up after itself — the half-finished uploads and the old versions both."*

these are not separate features to them. they are **one idea: a bucket that does not leak.** two of
the properties exist purely to stop a silent bill, and the consumer holds them as one thought with
versions, not as lifecycle trivia. that is why the wish bundles them, and why the shape keeps them
on one object.

🟢 **F16's shape matches that thought more closely than the flat one did.** the consumer says *"clean
up after itself"* about **three** subjects at once, and the nest names exactly those three —
`objects`, `versions`, `multiparts` — each with the same verb.

### the analogy that fits

**a safe-deposit box.** versions = keep every copy you put in. public-access block = only you have a
key. noncurrent expiry = shred copies older than a month. multipart abort = if you drop a document
half-way in, the staff clear the tray rather than bill you for the space.

the analogy also carries the sharp edge honestly: **once the box is a versioned box, it stays one.**
you can stop new copies (`status: 'suspended'`), but you cannot make it a plain box again. that is
invariant I-1, and it is intuitive in the metaphor in a way it is not in a type signature.

🟡 **and the analogy makes F16's forced key obvious too**: nobody keeps every copy forever *and*
declines to say when to shred them. the flat shape let you; the nest does not.

### their words vs ours

| they say | we say | note |
|----------|--------|------|
| "versions on" | `lifecycle.versions.status: 'enabled'` | aws's value, our letters (**F16** sub-call 1) |
| "not public" | `access: { public: 'blocked' }` | **F14** — the sub-fields drop the word and factor into a 2×2, so the path says *public* once: `access.public.acls.block` |
| "clean up old versions" | `lifecycle.versions.expire` | 🔴 **unreachable unless `status` is set** — that is the forced key |
| "clean up old files" | `lifecycle.objects.expire` | applies to ANY bucket, versioned or not |
| "half-finished uploads" | `lifecycle.multiparts.expire` | 🟡 drops aws's *incomplete*; the `.note` carries it — **F16** sub-call 3 |
| "it says KEEP" | convergence, no drift | the consumer's word for our whole acceptance criterion |

## .evaluation

### which warrant each property answers to

the wish justifies all four with one sentence — *"for a backup store they are not [optional] — see
the two failure modes below, both of which bill silently"*. those two failure modes cover **three**:

| property | warrant | how |
|----------|---------|-----|
| `lifecycle.multiparts.expire` | failure mode 1 — stranded parts | directly, it is the remedy |
| `lifecycle.versions.expire` | failure mode 2 — versions pile up | directly, it is the remedy |
| `lifecycle.versions.status` | failure mode 2 | as its **precondition** — and 🟢 **F16 makes that structural**: the remedy is a key on the precondition's own object, so the pair cannot be separated |
| 🔴 **`access.public`** | **neither — it bills no dollars** | see below |

🟡 **`lifecycle.objects.expire` and `.transitions` carry no warrant from this wish, and need none** —
they ship in `1.11.0` and F16 merely re-homes them. their inclusion is a **rename**, not a feature.

**a backup store's risk has two halves, and the wish's failure modes are both the cost half.** the
block serves the **exposure** half, and its warrant sits one paragraph earlier in the same `.why`:
the consumer wants a store *"write-only for the grove role"*.

⚠️ **and it is not redundant with the `DeclaredAwsS3BucketPolicy` that shipped in `1.11.0`.** a
bucket policy states what the **current** policy permits; a public-access block is an override that
refuses public ACLs and public policies **regardless of what any future policy says**. a policy
cannot forbid its own replacement — which is why aws ships both.

🔴 **that warrant is what settles F11**: if the block exists to make a backup store non-public, then
the cheapest way to write the field must mean **the secure default**, or the feature's own cheapest
path defeats the feature's own purpose.

🟢 **F15 then closed it at the TYPE rather than at the semantic.** F11 made `null` mean secure; F15
removed `null` from this subtree outright — the secure posture is the explicit token
`access: { public: 'blocked' }`, and `access` is required and non-nullable. the warrant above is
unchanged; what changed is that it no longer rests on a reader who knows what `null` expands to.

### against the wish's acceptance

| criterion | how the vision meets it |
|-----------|-------------------------|
| `versions` declarable | F1's union, re-homed by **F16** — `lifecycle.versions: false \| { status: 'enabled' \| 'suspended', expire }` + a `withAssure` guard on `status` |
| public-access block declarable | F2 — a nested dobj of four booleans + the frozen preset const `s3BucketAccessPublicBlocked`; **F15** adds the `'blocked'` token |
| lifecycle aborts incomplete multipart | `lifecycle.multiparts.expire` (**F16**), + the `.note` sub-call 3 owes |
| lifecycle expires noncurrent versions | `lifecycle.versions.expire` (**F16**) — 🟢 **and it is now unreachable unless `status` is set**, which is strictly stronger than the criterion asks |
| **each round-trips, no permadrift, absent cases covered** | case=1 (the KEEP) + case=2 (the three absent reads) + case=5 (the freshness window). 🟢 **the extant acceptance suite already gates this half** — `then('all resources show KEEP after apply')` fails the whole suite on any non-KEEP |
| 🔴 **the properties were actually WRITTEN** (not merely converged) | ⚠️ **NOT covered by any extant assertion, and this is the one new test the wish owes.** a property stripped from both operands — a `static readonly` entry, or a field never plumbed into the dobj — reads **KEEP**, and the suite passes green. an assertion must **read the declared values back off the applied bucket** |
| unmodeled value fails loud | case=4, invariant I-5. the **mechanism** is the cited `isDeclaredAwsS3StorageClass` precedent; the **message** is richer than that precedent emits (F8) |

#### 🔴 the contract surface needs a SECOND bucket

`resources.acceptance.ts` holds **exactly one** `DeclaredAwsS3Bucket` — `mailStore`, line 820 — and
it is disqualified from the wish's headline case on three counts:

| the wish's case | why `mailStore` cannot carry it |
|-----------------|--------------------------------|
| `versions: { status: 'enabled', … }` | ⛔ **it receives objects** — its own policy grants `ses.amazonaws.com` `s3:PutObject` into `inbound/*` (lines 833-850). per `case=7` a versioned bucket that holds objects **cannot be torn down**, and the leak burns a name in s3's **global** namespace |
| `Transitions: []` — the shape **A-6 / Q-9** is unverified about | ⛔ its lifecycle is a **staircase** (`GLACIER_IR` 30d, `DEEP_ARCHIVE` 180d, lines 823-827), so the empty-array wire shape is never sent |
| the **cleanup-only** fourth lifecycle mode | ⛔ that is the staircase mode with sub-rules layered on — `case=1`'s `[t4]` regression guard, not `case=1` itself |

⇒ **the split, and it is forced:**

- **`mailStore`** keeps its staircase under `lifecycle.objects`, and takes **`versions: false`** —
  the only safe value. the field carries a `.note` that says so, at the declaration, per
  `rule.prefer.prevent-over-correct`
- **a NEW object-free backup-store bucket** carries `case=1` verbatim. it carries a `.note` that
  names `case=7`'s object-free obligation **at its declaration**, since the constraint is
  unrecoverable if broken and a yield paragraph is rung 4 of the prevent ladder

🟢 **F16 makes `mailStore`'s edit smaller than the flat shape would have.** its extant `transitions`
and `expireAfterDays` move **wholesale** into `lifecycle.objects` — a re-home, not a re-think — and
the only genuinely new keys it takes are `versions: false` and `multiparts`.

🔴 **this new bucket is also where A-6 / Q-9 gets settled** — it is the only place in the suite that
sends `Transitions: []`, the exact wire shape the vision cannot verify from the sdk.

✅ **the cast snapshot is unaffected** — verified. `__snapshots__/castIntoDeclaredAwsS3Bucket.test.ts.snap`
holds exactly one entry, the `withAssure` rejection text for `ONEZONE_IA`, and no shape snapshot.

#### 🔴 a versioned test bucket must never receive an object

this is the wish's one hazard that lands on the **test harness** rather than on the product.
**a non-`false` `lifecycle.versions` invalidates the premise that makes this package's own s3 teardown safe** —
stated outright in `s3Bucket.journey.integration.test.ts` (*"this journey never puts objects, so del
is clean"*) and in `delBucket.ts`, whose `.note` records that a non-empty bucket **fails loud by
design**.

✅ **both halves are FETCHED from aws, not assumed** — so this is not an assumption and takes no `A-n`:

| aws says | source |
|----------|--------|
| *"All objects (**including all object versions and delete markers**) in the bucket must be deleted before the bucket itself can be deleted."* | `API_DeleteBucket.html` |
| *"If bucket versioning is enabled, the operation **inserts a delete marker** … To permanently delete an object in a versioned bucket, you must include the object's `versionId`."* | `API_DeleteObject.html` |

⇒ `empty` stops to be reachable by object deletes alone. **s3 bucket names are a global namespace**,
so a leaked fixture name is unusable account-wide.

**two findings the fetch turned up that the grid did not predict:**

1. 🔴 **`'suspended'` does NOT restore the safe teardown.** aws: under suspended versions a delete
   *"inserts a delete marker … If there isn't an object with a null `versionId` … Amazon S3 **does
   not remove the object**."* ⇒ the one legal retract aws offers (I-1, case=3) does not undo this.
   **so the harness constraint keys on `versions !== false`, never on `status === 'enabled'`.**
2. 🔴 **the demo role cannot clear the orphan by hand.** `resources.common.ts:45` + `:331-341` grant
   `s3:DeleteObject` on `'*'` — **and no `s3:DeleteObjectVersion`**. managed `ReadOnlyAccess` cannot
   supply it. `s3:ListBucketVersions` ✅ **does** come from `"s3:List*"` — so the operator can
   *enumerate* the versions they cannot *delete*. ⇒ a leaked versioned bucket needs **admin creds**.

| fixture | objects? | `lifecycle.versions` | verdict |
|---------|----------|-----------|---------|
| the journey bucket | never | must stay `false` on the teardown path | safe **today** |
| `mailStore` (acceptance) | **yes** — ses writes inbound mail to it | `false` | safe **only while it stays `false`** |
| a case=1 backup-store fixture | none | `{ status: 'enabled', expire }` | safe **only while it stays object-free** |

🟢 **F16 helps the harness here, slightly and genuinely.** `versions: false` is a **token a reader
recognizes as off**, where the flat `versions: null` read as *unset* — and *unset* is exactly the
value a hurried editor overwrites without a second thought.

⚠️ **the trap is that the unsafe combination is one line away.** `mailStore` is the natural bucket on
which to demo the property — it already exists — and it is the one bucket in the suite that receives
objects. **the obvious place to add the demo is the one place it must not go.**

### pros

- **the permadrift criterion drives every shape decision**, rather than a test bolted on at the end.
  F1 and F2 are both decided by "can this round-trip?", not by "which reads nicer".
- **one new write, three new api calls.** the two lifecycle sub-rules ride the extant
  `PutBucketLifecycleConfiguration`, so the foreign-rule guard (I-4) and the replace-all semantics
  cover them with no new work.
- 🟢 **the dao is untouched, and no new declared resource is added.** all four are fields on extant
  dobjs, so plan/apply drivability comes free — `rule.require.dao-and-acceptance-per-declared-resource`
  is already satisfied, and no provider registration or sdk export is owed.
- 🟢 **the secure posture is carried by the TYPE, not by a mechanism.** `access: { public: 'blocked' }`
  means all four true, expanded at construction exactly as the peer `metadataOptions` does. the
  asymmetry IS the pit of success: **the secure posture costs one token; the public-capable one
  costs four booleans, typed out** (F15, `rule.require.safe-by-default`). ⚠️ `public: true` is **not
  legal** — a symmetric token would make the exposed posture exactly as cheap as the safe one.
- 🔴 **the wish's second failure mode is now UNTYPEABLE, not merely guarded.** F5 closed it with a
  house rule — `rule.forbid.undefined-inputs` forces the consumer to type `null` (invariant I-3),
  rung **1** of the prevent ladder. **F16 moved it a rung deeper still**: `versions.expire` does not
  exist as a key unless `versions` is an object, so *"versions on, expiry forgotten"* is not a
  declaration the compiler can be persuaded to accept. ⇒ **demoed by
  [c11](1.vision.experience.case=11.typed-out-null-keeps-all-versions.md)**, whose argument F16
  strengthens rather than retires: the consumer who *means* an unbounded history must now write

### edge cases and the pit of success

| edge | how the contract keeps the consumer safe |
|------|------------------------------------------|
| retract versions to `false` | plan reads **UPDATE** (honest); **apply** rejects with a `BadRequestError` that names `status: 'suspended'` and the version-retention consequence, before its first s3 write (case=3). ⚠️ plan **cannot** be the rejection point — `computeChange` has no hook and `rule.forbid.plan-fail-on-apply-guided-prereq` forbids the `get` workaround as a blocker. 🔴 **F16 makes this edge MORE likely to be hit, not less** — `false` is an inviting token to type, where `null` read as *leave it alone* |
| a bucket found `status: 'suspended'` | representable, so it round-trips. a boolean model could not (F1) |
| a partially-blocked bucket | representable, so it round-trips. a `'blocked' \| null` literal could not (F2) |
| an aws value we do not model | throws at the sdk-read boundary with the field, the value, and the modeled set (case=4) |
| `access.public` omitted entirely | ⛔ **not reachable** — `rule.forbid.undefined-inputs` makes the field required, so a consumer must type `'blocked'` or the four booleans. the insecure state cannot be reached by inattention (F15) |
| 🟢 **versions on, noncurrent expiry omitted** | ⛔ **not typeable at all under F16** — `expire` is a required key on the same object as `status`, so the compiler refuses the declaration. this was legal-and-typed-out before; it is now **unrepresentable**, which retires I-3's softer guarantee upward |
| **versions on, expiry deliberately unbounded** | `expire: null`, typed beside the `status` that made it necessary. the only way to say *keep every version forever*, and it is a keystroke a human chose (c11) |
| noncurrent expiry on an unversioned bucket | ⛔ **also unrepresentable now** — `expire` lives inside the `versions` object, so `versions: false` has no place to put it. ⇒ **I-2's two-step-rollout concern is moot**: the rollout is one step, since enabling versions and setting their expiry are one edit |
| a foreign lifecycle rule on the bucket | the extant replace-all guard fails loud, unchanged (I-4) |
| an absent iam **write** grant | the apply fails loud, names the principal and both provisions to re-apply (case=6). ⚠️ the plan before it reads clean, so a green plan is no evidence the grants are live |
| an absent iam **read** grant | propagates loud — **never** degraded to `null`, which would be a phantom CREATE (case=6 `[t2]`) |
| 🔴 a **versioned ci fixture that received an object** | ⚠️ **the one unrecoverable edge**, so the guard is a **prevent** rung before a **teach** rung. ⇒ **prevent, at rung 3 — the constraint lives at the two declaration sites a hand would touch:** the new `case=1` bucket carries a `.note` that names case=7's obligation, and `mailStore` carries the inverse note at its `versions` field. 🔴 **the constraint keys on `versions !== false`, not on `status === 'enabled'`** — aws inserts a delete marker under suspended versions too, so a suspended fixture that receives an object is orphaned identically. ⚠️ **rung 1 is available and deliberately not taken** — a suite-level assertion costs a bespoke fixture-graph test; recorded so a later drive with more fixtures can take it knowingly. teach: `delBucket` already fails loud on a non-empty bucket and **never purges** |
| 🔴 an **actionless lifecycle object** — every sub-key empty | rejected at construction with `fix: lifecycle: null`, the idiom the shape's own doc already defines as the *persist* mode. newly **reachable** because `rule.forbid.undefined-inputs` forces every value to be typed; the guard holds whichever way aws answers Q-9 (case=8, I-6). 🟡 **F16 changes its SHAPE** — the check is now `objects.expire == null && objects.transitions.length === 0 && versions === false && multiparts.expire == null`, which reads more plainly than the flat four-null test it replaces |
| a **retry from a half-applied apply** | every write is independently idempotent, so a retry converges — **except** that a landed version-state put is a one-way door. the mitigation is the write **order** above: the version-state put runs **last**, so the irreversible step runs only after every reversible one succeeded |

⚠️ **the sharpest pit-of-success line in this wish** is that two rows live at the *same catch*, one
line apart, with opposite obligations: the absent-signal 404 must degrade to `null`; `AccessDenied`
must propagate. a single widened `||` converts a loud iam failure into a silent phantom CREATE
(`rule.forbid.failhide`).

## .what is awkward

honest discomforts, none of them a blocker:

1. 🟢 **~~the field name reads doubled~~ and ~~`restrictBuckets` is a plural on a single-bucket
   dobj~~ — BOTH RESOLVED by F14, in two passes, and the second pass is the one worth the note.**
   the drive's `publicAccessBlock.blockPublicAcls` said *public* twice; the wisher's
   `access.public.blockAcls` said it once. that left one residual, which this yield called
   **unrepairable by a better word** — ⇒ 🔴 **and that was wrong.** the 2×2 factor re-files
   `RestrictPublicBuckets` into the policy row on its own doc's evidence, so the plural disappears
   with the noun rather than needs a better word for it. ⚠️ both halves of the old argument survive:
   the two behaviours are still distinct and still two fields — now two fields **in one row**.

   🟡 **what remains awkward is the DEPTH.** `access.public.acls.block` nests three levels where the
   peer `metadataOptions` nests one, which is `howto.factor-an-attribute-set`'s own stated bound
   (*"depth beyond ~3 costs more than it saves"*) — taken at the bound, not past it, and paid in a
   `static nested` + a `.strict()` schema at each level.

2. 🟡 **~~the 38-character field name~~ — RESOLVED by F16, and it traded one discomfort for a
   smaller one.** `abortIncompleteMultipartUploadAfterDays` became `multiparts.expire`. the length is
   gone and so is aws's word *incomplete* — so the path is now **shorter than it is self-describing**,
   and a `.note` carries the difference (sub-call 3). ⚠️ the residual: a reader who never opens the
   dobj sees a label that is correct only because *a multipart upload* denotes an unfinished thing.
   ⇒ the ready repair is `multiparts: { abort }`, declined because `expire` names the motive the three
   sub-objects share where `abort` names one's mechanism.

3. **the wish's headline `.why` is answered by the TYPE, not by new code** — and F16 sharpened that
   rather than softened it. F5 argued the cost leak is guarded because `rule.forbid.undefined-inputs`
   forces the consumer to type `null`; F16 goes further and makes the omission **unrepresentable**.
   that is genuinely the pit of success — and it remains a *smaller* answer than the wish's frame
   implies. [c11](1.vision.experience.case=11.typed-out-null-keeps-all-versions.md) is the argument
   that it is smaller AND better: rung **1** of `rule.prefer.prevent-over-correct`'s ladder, because
   unlike a release note, a lint rule, or a doc-comment, **it cannot be skipped: the code does not
   build.** ⚠️ the residual awkwardness stays, and F16 deepens it: a reader who wants the guard to
   look like work will find *even less* to look at, since the guard is now a key's position.

4. **the design fights the mental model at one point, and it is aws's fault.** a consumer thinks
   "turn versions off". aws offers no such move. we surface a `BadRequestError` that teaches the real
   model (case=3) — the best available outcome, but the tool still has to correct the user's picture
   of the world rather than serve it. 🔴 **F16 makes this edge easier to reach**: `versions: false` is
   an inviting token to type, where the flat `null` read as *leave it alone*.

5. **the freshness fix touches code this wish did not set out to change, and F16 enlarged it.** the
   predicate is blind to **any** write that does not change `transitions.length`, so it already fails
   on the shipped `expireAfterDays: 30 → 60` path with no part of this wish present. ⇒ **the fix is
   OWED by the wish, not donated to it**, and the throw is required outright by
   `rule.forbid.failhide`. ⚠️ **but under F16 the predicate must now walk three sub-objects** rather
   than widen from one field to four — so the repair is a rewrite, not an extension. what survives is
   a **review cost**: the diff for an additive wish includes a repair to shipped behaviour, so a
   reviewer grades two things at once.

6. **case=6 cannot be closed by the drive.** the iam re-apply is interactive and admin-only. the
   vision can name it precisely and no more; ci will be red between merge and that human action.
