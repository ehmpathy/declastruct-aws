## .narrative

vlad's backup store has carried an all-four-true public-access block since case=1. six months on,
the account moves exposure control to an org-level policy, so the per-bucket block is redundant. he
deletes the field from his wish — which under option (a) is `access: { public: null }` — and applies.

```
○ ahbode-camp-git-backup
   ├─ ✔ done in 0.38s
   └─ decision [UPDATE]
      - Remote
      + Desired

        "access": Object {
      -   "public": Object {
      -     "acls": Object { "block": true, "ignore": true },
      -     "policies": Object { "block": true, "restrict": true },
      -   },
      +   "public": null,
        }
```

`🤙 yolo, plan auto approved...` · `🪄  apply changes...` · `   └─ ✔ done in 1.2s`

he re-plans to confirm. **UPDATE.** the same diff, unchanged. he applies again — success again. and
again. **the apply reports success every single time and the state never moves**, because a `null`
desired that issues no call writes no change, and the read-back faithfully returns the block that is
still there.

⚠️ **this is the wish's decisive criterion broken in its purest form** — not a canonicalization
mismatch, not a stale read, but a **write that was never issued at all**. and it is the worst variant
of permadrift, because every other permadrift in this vision is a *read* defect that an operator
might eventually suspect. here the apply is honest about what it did: it did what it was asked, and
what it was asked was empty.

## .the `[tn]` timeline

```
given  [case9] a bucket whose access.public is set — all four true
  and  a wish that now declares access: { public: null }

  when [t0] plan runs
  then  the read returns the extant block and desired is null
   and  the decision is [UPDATE]
   and  it is NOT KEEP — a change WAS declared, so UPDATE is honest here
        (contrast c2, where UPDATE would be the defect)

  when [t1] apply runs set.upsert
  then  it CALLS delPublicAccessBlock
   and  it does NOT skip the write on the grounds that desired is null
        (a null desired that issues no call is the permadrift itself)

  when [t2] the read-back runs
  then  GetPublicAccessBlock raises the absent-signal error        # A-5 / Q-1b
   and  the COMMUNICATOR degrades it to null, and does not throw
   and  the cast yields access: { public: null }

  when [t3] the caller re-plans
  then  the decision is [KEEP]

  when [t4] apply runs AGAIN against a bucket that already has no block
  then  the SET converges, and an absent block is the desired END STATE
   and  it converges EITHER because aws's del is itself idempotent
                     OR because the set gates the del on a read-first guard
   and  which of the two is owed is settled by A-7's live call
        (an unconditional del against an unverified api is NOT the contract)

  when [t5] the role lacks the delete grant                        # A-7
  then  the apply THROWS AccessDenied, which names the action aws wanted
   and  it does NOT degrade to success
   and  it does NOT degrade the subsequent read to null
        (that would be a phantom CREATE - c6 [t2])
```

### what the timeline catches that the narrative does not

- **`[t0]`'s "it is NOT KEEP"** — the sharpest line in this case, and it inverts c2's. in c2 an
  UPDATE **is** the defect; here an UPDATE is **correct**, and a KEEP would be the defect. ⇒ *the
  same decision is right or wrong according to whether the consumer declared a change* — which no
  single-case read of "converges to KEEP" would tell an implementer, and which a narrative cannot
  show because vlad only ever sees one of the two.
- **`[t1]`'s "does NOT skip"** — the whole defect in one beat. it is a **write-side** omission, and
  every other permadrift in this vision is read-side, so an implementer who has internalized the
  other cases is primed to look in the wrong layer.
- **`[t2]`'s "the COMMUNICATOR degrades it"** — names the layer. the absent-read normalization lives
  in `getPublicAccessBlock`, not in the cast; by the time a value reaches the cast it is already
  `null` (see the yield's internal-research row). an implementer who put the catch in the cast would
  place it **downstream of the throw that aborts the plan**.
- 🔴 **`[t4]` — the retract's own idempotency, stated as a DISJUNCTION rather than a promise.**
  `set.upsert` runs on every apply, so a converged bucket re-enters this path forever. ⚠️ **whether
  aws's `DeletePublicAccessBlock` is itself idempotent on a bucket with no block is unverified** — it
  is folded into **A-7**'s live call, since it is the same call on the same path.

  ⚠️ **corrected by peer review r2.** an earlier draft wrote the then-clause as *"the operation
  converges and does NOT throw … (del* is idempotent here, exactly as delBucketLifecycle is)"* — and
  then hedged it, one line down, with *"is unverified."* ⇒ **a `[tn]` then-clause is a contract, and
  a contract that asserts an unverified api behaviour is not a weak contract — it is a false one.**
  the beat now asserts what is genuinely owed (convergence) and leaves the **mechanism** open along
  A-7's two branches, so an implementer who reads only the timeline cannot mistake *"aws is idempotent
  here"* for a settled fact and skip the guard.

  ⇒ this is the vision's own *"do not implement from a guess"* pattern, applied to a beat rather than
  to a fulcrum — the same discipline A-5, A-9 and Q-9 already carry.
- **`[t5]`'s two "does NOT degrade" lines** — the same one-line-apart hazard c6 names: the absent-
  signal 404 must become `null`, and `AccessDenied` must propagate. a widened `||` at this catch
  turns a loud iam failure into a silent phantom CREATE (`rule.forbid.failhide`).

## .the fail-safe — graded against the clauses

⚠️ **added by peer review r2**, which noted that every other sharp critipath in this set grades its
edge explicitly and that c9 and c10 left the proof implicit inside their beats. its diagnosis is the
reason it matters: *"since the case was added by review precisely because a critipath was promoted and
never demoed, the fail-safe half of the demo is the part most likely to be assumed rather than
written."*

🔴 **and c9 is a special case of the rubric, which is why it is worth a full grade rather than a copy
of the pattern:** every other sharp case in this set fails safe by **a throw**. c9's primary edge is
the opposite shape — **an omission**, a call never issued — so clauses 1 and 2 grade *whether the
write happens at all*, not how loudly it fails.

| # | clause | c9's proof |
|---|--------|-----------|
| 1 | **fast** | the retract is issued in the **same `set.upsert`** as every other write, so the state converges before the set returns. ⚠️ **the failure mode this clause guards is not slowness — it is a branch that returns early on `desired === null`.** "fast" here means *the call is reached*, and `[t1]` asserts exactly that |
| 2 | **loud** | 🔴 **the sharpest clause in this case, because the silent path is the DEFAULT one.** a skipped write produces a **green apply** and an unchanged bucket — the failure is loud only via the caller's re-plan (`[t3]`), never at the moment of the defect. ⇒ so the loudness is bought by the KEEP assertion, and that is why `[t3]` is a beat rather than a footnote. the two paths that *do* throw — an unknown read error, and `[t5]`'s `AccessDenied` — must propagate and never degrade to `null` |
| 3 | **teaches the fix** | `[t5]`'s denial names the action aws wanted (`s3:DeletePublicAccessBlock` or whichever A-7 settles on), which is what routes an operator to the two-target re-apply c6 documents. ⚠️ the permadrift itself teaches **no** fix — there is no error to carry one — which is a second argument for `[t3]`'s guard |
| 4 | **holds the limit** | **vacuous at this cell** — the edge is a presence/absence pair, so there is no *last valid input*. ⚠️ scoped per c4's corrected text: vacuous **here**, never in the space |
| 5 | **drops no data silently** | ✅ **the retract IS a deliberate data drop, and that is what makes clause 5 live rather than trivial.** the consumer asked for the block to go; the guarantee owed is that it goes **exactly when asked and never otherwise** — so `[t4]`'s convergence (an already-absent block is the end state, by whichever of A-7's two mechanisms holds) and `[t5]`'s propagate-never-degrade are both clause-5 obligations |

⇒ the through-line across the five: **c9's failure is an absence, so four of the five clauses grade a
call that must be REACHED, rather than an error that must be well-formed.**

## .why this is a critipath

- **frequency** — moderate on its own; but it is reached by **every** apply of **every** consumer
  whose bucket has no block, since `set.upsert` traverses this branch each run. the retract is rare;
  the *branch* is universal.
- **cost** — a permadrift the wish's decisive criterion forbids by name, and an apply that reports
  success while it changes no state. worse, it drops a security retract **silently in the safe
  direction** — the block stays on — so the only symptom is a plan that never settles, which reads as
  a tool defect rather than a state defect and is the class this repo records as most costly to trace
  (`hazard.local-green-cicd-red`).

`freq × cost` high on both → **critipath**, exactly as the census regraded it.
