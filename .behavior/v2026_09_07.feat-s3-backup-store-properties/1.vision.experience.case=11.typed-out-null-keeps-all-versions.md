# case=11 — a typed-out `null` keeps every version, deliberately

**feel** happy · **care** 🔴 **alterpath** — the first and only alterpath with its own demo ·
**actor** `consumer` · **cells** 22 (`expireNoncurrent · null · absent`), invariant I-3

⚠️ **added by peer review r2 (verified11, nitpick.1).** the reviewer graded the nine itemized
alterpaths a nitpick — correctly, since `rule.require.experience-coverage` states outright that
*"alterpaths beyond the critipaths strengthen the picture but are not required"* — and then named
**which** one it would sketch: cell 22, *"the wish's headline cost-leak inverse"*.

🔴 **it named the right one, and for a reason larger than the nitpick.** cell 22 is the only cell in
the census that **demonstrates the wish's own pit-of-success argument**. `F5` claims the cost leak is
closed at zero code cost, because `rule.forbid.undefined-inputs` forces the consumer to type `null`
with `versions` in view. that claim is asserted in the yield's `.pros`, in its `.what is awkward`
section, and in invariant I-3 — **and until now it had no demo anywhere.**

⇒ **this case is not padding on a nitpick. it is the missing evidence for a claim the vision leans on
three times.**

## .narrative

kai declares a bucket to hold audit records under legal hold. the requirement is plain and it is the
opposite of the wish's headline scenario: **every version must be retained, indefinitely.** no expiry,
no cleanup, ever — a deleted or overwritten record must remain recoverable for as long as the hold
stands.

he starts with the property that makes that possible — and **the compiler will not let him write it
alone**:

```
error TS2741: Property 'expire' is missing in type '{ status: "enabled"; }'
  but required in type '{ status: DeclaredAwsS3BucketVersionsStatus; expire: IsoDurationInDays | null }'.
```

so he answers it, **on the next line, in the object he is already inside**:

```ts
lifecycle: {
  objects:    { expire: null, transitions: [] },
  versions:   { status: 'enabled', expire: null },  // ← keep every version. legal hold.
  multiparts: { expire: { days: 7 } },              // stranded parts still get cleaned
},
```

that single `null`, and the comment beside it, is the whole case.

### 🟢 F10 WEAKENED this case's sharpest claim. **F16 GAVE IT BACK — and then some.**

⚠️ **the first half was found 2026-09-09**, by the audit this drive committed to: *when a verdict
lands, grep the other entries for the premise it just moved.* this case originally argued that the
question is asked **at the keystroke that enables versions** — *"not at the first bill"* — and that
adjacency was the argument, not decoration.

**F10 separated the two.** the noncurrent expiry sat on the bucket's lifecycle; `status: 'Enabled'`
sat on a different declared resource, possibly written minutes later and several lines away.

🟢 **F16 re-joined them into one object, and went past where F10 found them.** the two keys are now
not merely in the same object — **`expire` is unreachable until `status` is written**, because the
forced key admits no half-object. ⇒ the question is asked *later* than at the versions keystroke; it
is asked **at** it, as the second half of one indivisible act.

| | pre-F10 | post-F10 | 🟢 post-F16 |
|---|---|---|---|
| **is the question forced?** | 🟢 yes — required-nullable | 🟢 yes, unchanged | 🟢 **yes** |
| **is it asked with `versions` in view?** | 🟢 yes — same object, adjacent lines | ⛔ no — a different object, possibly written first | 🟢 **yes, and STRICTLY so** — it is a key of the `versions` object, unreachable without it |
| **can the hazard be reached by inattention?** | ⛔ no | ⛔ no | ⛔ **no — and now by CONSTRUCTION** |
| **can it be answered for a bucket not yet versioned?** | ⚠️ yes | 🔴 **yes — the post-F10 failure mode** | 🟢 **no. the key does not exist until versions do** |

⇒ 🔴 **the post-F10 failure mode this section named is now unrepresentable.** it read: *"a human who
answers correctly for a bucket that is not yet versioned, then enables versions later and never
revisits the answer."* under F16 there is no answer to give until versions are on, and the act of
turning them on **is** the act of answering. **the ergonomic regression F10 caused is not mitigated;
it is deleted.**

🟢 **so the case's original sharpest claim is restored verbatim** — the compiler asks at the
keystroke that enables versions — and this case is once again the demo for it.

⚠️ **and that raises rather than lowers its value as a demo.** the claim it now carries is the
strongest one in the vision: not *"the type forces an answer"* (F5, true under every shape here) but
*"the type forces the answer **at the only moment the answer is meaningful**"*. that is
`rule.prefer.prevent-over-correct` **rung 1**, and c11 is where it is shown rather than asserted.

### 🔴 what the type did, in the moment it did it

kai was asked *"how long do you keep old versions?"* **at the exact moment he turned version history
on**, by the compiler, in the file he was already editing. he could not proceed without an answer. he
gave one, and it is a real answer: **forever.**

| | what happened |
|---|---|
| **when** the question was asked | 🟢 **post-F16: at the keystroke that turns versions on** — the sentence above is literal again. the `expire` key does not exist until `status` is written, so the two are one act. ⇒ see the F16 section above |
| **who** asked it | the type, via `rule.forbid.undefined-inputs`. no reviewer, no lint pass, no runbook |
| **what** a wrong answer costs | ⛔ none here — kai's answer IS `null`, and it is correct for his case |
| **what an ABSENT answer would cost** | 💸 the wish's headline failure mode: versions pile up, silently, billed monthly |

## .the fail-safe — and why a happy path has one

⚠️ **this is a `happy` cell. it has no error to demo, no throw, no rejection.** its fail-safe is
structural rather than reactive, and that is precisely what makes it worth a case: **the guard is
that this path cannot be reached by inattention.**

🔴 **the sharpest fact in this wish is that cell 22 and the wish's headline hazard are the SAME
DECLARATION.** a versioned bucket with no noncurrent expiry is either:

| | the same wire state | told apart by |
|---|---|---|
| **kai** — a legal hold | `NoncurrentVersionExpiration` absent | he **typed** `null` |
| **the hazard** the wish exists to prevent | `NoncurrentVersionExpiration` absent | it was **never considered** |

⇒ aws cannot tell these apart. the bill cannot tell them apart. **the only thing that distinguishes a
deliberate retention from an accidental cost leak is whether a human was asked.**

so the fail-safe is not a check on the *value* — `null` is legal and must stay legal (invariant I-3
exists to keep it so). it is a check on the *provenance* of the value:

```ts
// what rule.forbid.undefined-inputs buys, stated as the guarantee it actually is:
//   there is no way to produce a versioned bucket with absent noncurrent expiry
//   WITHOUT a human typing `null` at that field.
```

⚠️ **and this is exactly the guarantee an optional field would destroy.** under `expire?:
IsoDurationInDays`, kai's declaration and the hazard's declaration become **byte-identical source** —
both simply omit the key. the distinction would not be weakened; it would cease to exist.

🟢 **F16 added a second, independent guarantee beside that one.** the first says *a `null` must be
typed*; the second says *the field cannot be typed at all on a bucket without versions*. ⇒ the
hazard the wish names — **versions on, expiry forgotten** — is now barred twice: once by
`rule.forbid.undefined-inputs`, once by the shape. **and the second bar holds even if the first were
repealed**, which is the property that makes it worth stating separately.

### 🔴 why this is stronger than a lint rule or a doc

the yield's `.what is awkward` section flags that F5's answer *"is a smaller answer than the wish's
frame implies"*. this case is the argument that it is smaller **and better**:

| instrument | when it fires | can it be skipped? |
|---|---|---|
| a release note | when read | ✅ trivially |
| a lint rule | at ci | ✅ disabled, or the file is out of scope |
| a doc-comment | on hover | ✅ if the cursor never lands there |
| 🔴 **a required-nullable field** | **at compile, always** | ⛔ **no — the code does not build** |

⇒ it is rung **1** of `rule.prefer.prevent-over-correct`'s ladder — *"make it impossible"* — reached
without a line of bespoke code, because the house rule already put it there.

## .the `[tn]` timeline

```
given  [case11] a consumer who must retain every version indefinitely (legal hold)
  and  a bucket with NO lifecycle configuration written at aws yet

  when [t0] they write versions: { status: 'enabled' } and stop
  then  the compiler REFUSES the build until `expire` is given
   and  the question is asked at COMPILE, always, and cannot be skipped
   and  ⚠️ this step is the whole pit of success; it is invisible in the final source
   and  🟢 post-F16 it is asked at the VERSIONS keystroke — the guarantee AND the
        adjacency both hold. see the F16 section above

  when [t0b] they had instead written versions: false
  then  🟢 NO expiry question is asked, and none is owed — the key does not exist
   and  ⛔ there is no path by which they answer it "for later"  (the post-F10
        failure mode, now unrepresentable)

  when [t1] they answer null — the deliberate keep-all-versions choice
  then  the declaration is legal, and NO construction guard fires
   and  ⚠️ a guard here would be a DEFECT: invariant I-3 requires null stay legal

  when [t2] plan runs against the bucket
  then  getBucketLifecycle returns a config with NO NoncurrentVersionExpiration key
   and  the communicator degrades that OMITTED sub-object to null   # cell 22, D = absent
   and  remote null === desired null, so the property contributes NO diff

  when [t3] apply runs and the lifecycle put is issued
  then  the rule carries AbortIncompleteMultipartUpload and NO NoncurrentVersionExpiration
   and  aws stores exactly that
   and  🔴 PutBucketVersioning{Status:'Enabled'} is ALSO issued, from the same
        declared `versions` object  (F16 sub-call 2 — one field, two calls)

  when [t4] the plan is re-run
  then  it reads KEEP                                              # the convergence claim
   and  it does NOT read a spurious UPDATE from null-vs-omitted    # the permadrift trap

  when [t5] a SECOND consumer omits the field entirely
  then  ⛔ there is no such consumer — the code does not compile
   and  ⚠️ this step has no observable behaviour, and that is the point:
        the failure mode this wish exists to prevent is UNREACHABLE IN SOURCE
```

### what the timeline catches that the narrative does not

- **`[t0]` is the load-bearing step and it leaves no trace in the artifact.** read kai's final
  declaration and you see a field set to `null`; you cannot see that the compiler *demanded* it. the
  narrative shows the outcome; only a step can show the coercion that produced it.
- 🔴 **`[t1]`'s "no guard fires" is an anti-assertion, and it is owed.** case=8 adds a construction
  guard to this same lifecycle shape. an implementer who over-broadens that guard to *"reject a
  lifecycle that declares no cleanup"* breaks **this** case. `[t1]` is the step that says: the
  actionless guard must fire only on *empty `objects` AND every expire null AND `versions === false`*,
  and kai has a live `multiparts.expire` **and** a `versions` object, so he is legal twice over.
  ⇒ **c8 and c11 bound the guard from opposite sides**, and 🟢 **F16 widened kai's margin**: under
  the flat shape his sole defence was one non-null day-count; under F16 his `versions` object alone
  clears the fourth term, whatever his expiries say. see c8's `[t3b]`, which is that margin stated
  from the guard's side.
- **`[t2]`'s omitted-vs-null degrade is cell 22's actual mechanism**, and it is the third of the
  wish's three absent-read shapes (an *omitted sub-object*, distinct from c2's empty body and 404).
  c2 demos the shape on a bucket with no properties at all; **c11 demos it on a bucket that has a
  live lifecycle rule with the sibling sub-object present** — which is the harder read, because the
  parent object exists and only the child is absent.
- 🔴 **`[t5]` asserts a non-event, which no narrative can do.** *"the hazard has no representation in
  source"* is a claim about the set of writable programs, not about any execution. a timeline can
  state it; prose can only assert it.

## .the counterfactual — why an alterpath earned a demo at all

`rule.require.experience-coverage` does not require this case, and the census does not claim it does.
it earns its place on three counts:

1. 🔴 **it is the only evidence for F5.** the pit-of-success argument is cited three times in the
   yield and demoed nowhere. an argument asserted three times and demonstrated zero times is the
   shape this drive has repeatedly caught itself in — *a fact in prose that never reached the
   structure*.
2. **it bounds c8's guard from the other side.** without `[t1]`, the actionless-lifecycle guard has
   only its own case to constrain it, and the natural over-broad predicate silently forbids a legal
   declaration.
3. **it demos the third absent-read shape on its hardest surface** — a present parent with an absent
   child.

⚠️ **and the honest limit: it is still `happy · alter`.** no one is hurt if this case is never
written; the consumer's path works either way. what is lost without it is not a user's safety but a
**reviewer's ability to check the wish's central ergonomic claim** — which is a real cost, and a
smaller one than a critipath's.
