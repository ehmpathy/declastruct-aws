# wish: declastruct-aws — SSM param name must encode the SSH comment (breaks on `@`)

## .what

`DeclaredAwsEc2SshKeyAuthorized` composes its SSM Parameter Store name from the SSH
key **comment, verbatim**:

```
/declastruct/ec2/ssh-keys/${instance.exid}/${comment}
```

SSM param names allow only `[A-Za-z0-9._-]` per path segment. SSH key comments
default to `user@host` (ssh-keygen), so the `@` makes AWS reject the name. encode
the comment into an SSM-safe token when the param **name** is composed — identically
across get / set / del.

## .why

breaks for **essentially every real SSH key** — the ssh-keygen default comment is
`user@host`. an operator must hand-edit their key comment to a `@`-free token to get
past it (not pit-of-success), and the failure surfaces deep in an AWS call with a
cryptic `ValidationException` catch-all message.

## .source (authoritative)

read the upstream issue first — it is the source of truth (handoffs-at-source):

- `ehmpathy/declastruct-aws#73` — the task handoff (full repro, cause, solution)

## .cause (both name sites)

both interpolate `comment` straight into the param name:

- `src/domain.operations/ec2SshKeyAuthorized/getOneEc2SshKeyAuthorizedByUnique.ts:12`
- `src/domain.operations/ec2SshKeyAuthorized/setEc2SshKeyAuthorized.ts:55`

audit for a `del` site too — get / set / del MUST derive the name the SAME way, or a
re-plan will not find the key it just wrote.

## .required solution

encode the comment into an SSM-safe token when the param **name** is composed. the
human-readable comment already lives in the param **value** (`setEc2SshKeyAuthorized`
stores `comment` inside the JSON value), so the name only needs a stable, unique,
SSM-safe key.

- **preferred**: a deterministic hash of the comment (sha256 hex) — fully SSM-safe,
  no collision surface; the name stays an opaque key, the readable comment rides in
  the value.
- **acceptable**: a reversible SSM-safe encode.
- **do NOT ship the naive** `comment.replace(/[^A-Za-z0-9._-]/g, '_')` — it collides
  two distinct comments onto one name. (ahbode/infrastructure used it as an ephemeral
  local `node_modules` patch to unblock a live apply; the durable fix is this task.)

extract the name derivation into ONE shared transformer so get / set / del cannot
drift apart.

## .acceptance

- a key with a default `user@host` comment composes a valid SSM param name (no `@`,
  only `[A-Za-z0-9._-]` per segment) and `declastruct plan` no longer throws
  `ValidationException`
- get / set / del all derive the name via the SAME shared transformer (proven by a
  test that the three agree for a given comment)
- two distinct comments derive two distinct names (no collision — rules out the naive
  replace)
- the readable comment is still stored in the param value (unchanged)
- test coverage for the name-derivation transformer (default `@` comment, plus edge
  chars) + the get/set/del agreement
