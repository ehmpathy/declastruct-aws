## design decisions (from the vision)

- **fulcrum A (collapse)**: `null` declaration = secure default. set expands `null ->
  {required,1,enabled}`; cast collapses a read-back that equals the secure default back to
  `null`. so a secure-by-default template converges to KEEP against an omitted declaration,
  an opt-out (`optional`) or docker (`hop 2`) reads back explicit (non-collapse -> KEEP), and
  a PRE-FEATURE template with no `MetadataOptions` (aws omits it → imdsv1-allowed) reads back
  the AWS implicit default `{optional,1,enabled}` (`ec2InstanceMetadataOptionsAwsImplicit`),
  which does NOT collapse — so it plans a change against a null (secure) declaration and,
  since the template is immutable, apply fails loud → prune-then-recreate. this is the
  honest live read (`rule.require.immutable-source-of-truth`) that avoids a false KEEP
  masking an insecure box (`rule.forbid.failhide`). no public-contract change.
- **launch-template-only scope** (vision assumption 1, [wisher]-flagged): the instance is
  launched from the template at `$Latest` and inherits its `MetadataOptions`, so the box is
  hardened without a change to `setEc2Instance` / `RunInstancesCommand`. the instance-path
  per-instance override is a scoped follow-up.
- **three of six sub-fields** (vision assumption 4): model `httpTokens` /
  `httpPutResponseHopLimit` / `httpEndpoint`; omit `HttpProtocolIpv6` + `InstanceMetadataTags`
  (both default `disabled`, KEEP-safe), and the read-only `State`. additively extensible.
- **no DAO needed**: `DeclaredAwsEc2InstanceMetadataOptions` is a nested value object (a
  `DomainLiteral`, like `DeclaredAwsEc2InstanceNetwork`), not a standalone get/set-able
  resource. it rides on the launch template's extant DAO + acceptance coverage.

## follow-up (scoped, not in this behavior)

  needed for a per-instance override that differs from the template; the box already inherits
  the template's secure default. flagged for the wisher.
- widen to `HttpProtocolIpv6` / `InstanceMetadataTags` if a future caller needs them.

## REQUIRED at the verification stone — prune-then-recreate the ec2 fixtures

`metadataOptions` is an IMMUTABLE launch-template attribute. the acceptance + demo ec2
fixtures (template + instance) were created BEFORE this feature, with no `MetadataOptions`.
the new field changes an immutable attribute, so a plain re-apply computes UPDATE and
`setEc2LaunchTemplate.upsert` fails loud (templates are immutable). per
`rule.forbid.test-blocking-orphans`, prune the extant fixtures FIRST, then re-apply so they
free-create secure:

```sh
# acceptance fixtures
./provision/aws.infra/account=demo/aws.prune.ec2.sh \
  --template declastruct-acceptance-template  --instance declastruct-acceptance-instance
./provision/aws.infra/account=demo/aws.prune.ec2.sh \
  --template declastruct-acceptance-nat-template --instance declastruct-acceptance-nat
# demo provision fixtures: prune the hibernator + nat templates/instances the same way
```

after prune + re-apply:
- the fresh templates carry the secure default (required/1/enabled) and read-back-collapse to
  null -> KEEP
- the fresh acceptance instance inherits imdsv2 -> the new "box inherits IMDSv2" acceptance
  assertion (live DescribeInstances read) passes. if the prune is skipped, that assertion
  fails loud (no silent false-KEEP).
