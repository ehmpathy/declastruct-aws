## flagged for review (fulcrums / notes forward)

1. **journey case unrun locally.** the ubuntu journey case needs real AWS creds (not sourced
   here; adhoc AWS is against durable feedback), so CI is its FIRST real run. design choices
   to review: (a) AMI look-up via Canonical owner+name filter, (b) raw
   `DescribeLaunchTemplateVersions` teeth read (needed because the domain object drops
   `DeviceName`). the deterministic UNIT test is the guaranteed-teeth clamp; the journey is the
   end-to-end confirmation the wisher asked for (acceptance #5).
2. **error class = `UnexpectedCodePathError`** (wish default, file-symmetry). the alternative
   `ConstraintError` (an absent name ≈ a caller's bad `imageId`, exit-2) was considered and
   deferred to this default; flag if a reviewer prefers the caller-fault class.
3. **`rootDeviceName?` override — OUT of scope** per wisher decision (lookup-only ships).
4. **release note owed** (wish `.scope`): external callers on a hand-scoped ec2 policy (no
   `ReadOnlyAccess`/`AmazonEC2ReadOnlyAccess`) must add `ec2:DescribeImages`. this repo's own
   roles already hold it. cut as a minor (additive, no contract break).
5. **read-path device allowlist — NOW FIXED in-scope (promoted by l3 blockers r10 + r11).**
   the two l3 peer reviews (enroll-impl-behavior-intent + enroll-impl-arch-defects) both blocked
   on the same hazard: `castIntoDeclaredAwsEc2LaunchTemplate.ts` read the root volume by a
   hardcoded `'/dev/xvda' || '/dev/sda1'` match, so a 3rd AMI family read back the defaults →
   permanent drift (`rule.require.immutable-source-of-truth`). they were right that this is the
   one spot where the wish's "any AMI family" goal was not achieved end-to-end, so it belongs in
   THIS fix. generalized the read to `blockDevices.find(knownNames) ?? blockDevices[0]` (the set
   op emits exactly one block device, so the sole-device fallback is a general, I/O-free read that
   keeps the cast a pure transformer). added a `/dev/nvme0n1` 3rd-family clamp. no longer a
   deferred follow-up.
