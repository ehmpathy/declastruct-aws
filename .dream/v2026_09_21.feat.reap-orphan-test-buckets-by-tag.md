# 🌙 dream: reap orphan test buckets by tag

**kind** feat · **owner** whoever holds the s3 test lane · **caught** 2026-09-21

## .the cue that fired

the 5.1 blocker claimed *"no orphan buckets leaked"* on the strength of a **read of the teardown
path** — an inference, never a measurement. a re-read to verify it found the inference rested on a
false premise.

`s3Bucket.journey.integration.test.ts`:

```ts
const testName = `declastruct-test-s3-${genTestUuid().slice(0, 8)}`;   // fresh uuid PER RUN
...
// cleanup before: remove any leftover from a prior crashed run        // 🔴 it cannot
await delS3Bucket({ by: { unique: { name: testName } } }, context);
```

⇒ 🔴 **the comment was a lie the code could not keep.** a crashed run's bucket sits under a
*different* uuid, so a delete keyed on this run's fresh name reaps naught. the `beforeAll` reads as
an orphan sweep and is a guaranteed no-op.

## .the gap, precisely

`rule.require.ec2-test-cleanup-both-ends` is explicit that the before-half must sweep **by tag**:

> beforeAll: terminate any instances with test tag

the bucket already carries the tag — `{ managedBy: 'declastruct', purpose: 'integration-test' }` —
so the data is there; only the enumeration is absent.

| journey | before-half sweep | correct? |
|---|---|---|
| `vpc.journey` | `getAllVpcs({ by: { tags: TEST_VPC_TAGS } })` → `delVpcCascade` each | ✅ the precedent |
| `s3Bucket.journey` | `delS3Bucket({ by: { unique: { name: testName } } })` | 🔴 no-op |

⚠️ **the leak is unbounded and silent.** every crashed or denied run strands a bucket that no later
run can find. unlike the vpc case there is no quota to trip, so naught ever fails loud — the cost
just accrues.

⇒ the 2026-09-18 and 2026-09-20 runs each failed 7/7 on a denial. whether their buckets survived
turns on how far `setS3Bucket` got before the throw and whether `afterAll`'s delete was itself
denied. **that is measurable and was not measured** — see the ask below.

## .the shape of the fix

1. `getAllS3Buckets({ by: { tags } })` — a new domain op: `ListBuckets`, then the per-bucket tag
   read, filtered to the tag set. mirror `getAllVpcs`'s contract exactly
2. swap the journey's `beforeAll` to enumerate + reap, and keep the `afterAll` as-is
3. 🔴 **grant `s3:ListAllMyBuckets`** in `demoPermissionsPolicy` — `s3:ListBucket` is the
   object-level peer and does NOT cover the account-level enumeration
4. per `rule.always.keep-the-cicd-role-in-sync-with-the-tests`, that grant must reach every role
   that consumes it from ONE tree — the same constraint that halted stone 5.1

## .why it is not done in this round

it fails **CLEAN**, plainly: a new domain op + a new sdk call + a new grant is not a ride-along on
an s3-properties diff.

⇒ and step 3 is decisive — **the grant lands in the exact two-tree apply this stone is already
halted on**, so the fix cannot be verified until that unblocks. to author it now would add
unrunnable code to a branch whose lane is already red.

⚠️ the deferral is a **dirt** call, so it owes a fulcrum beside this dream: `F19`.

## .the ask that is cheap and was not run

before this lands, one read settles the open question:

```sh
aws s3api list-buckets --query "Buckets[?starts_with(Name, 'declastruct-test-s3-')].Name"
```

a human with demo creds can run it in a second. **an empty result confirms the blocker's original
claim; a non-empty one names the leak and dates it.** the driver cannot run it — the enumeration is
the very action that is ungranted.
