# 🌙 dream: teach the `account=demo` apply howtos to source the reach env

**kind** fix · **owner** whoever merges `beav/feat-demo-trusts-ahbode-grove` · **caught** 2026-09-21

## .the cue that fired

stone 5.1 halted on an iam gap, and the remedy turned out to be a merge of
`beav/feat-demo-trusts-ahbode-grove`. a read of that branch's
`provision/aws.auth/account=demo/resources.ts` shows it calls `getOneCampReachIdentityFromEnv()`
**at the composition root**, which throws when either var is absent.

⇒ so the moment that branch merges, **every `account=demo` apply gains a required step** that no
current howto mentions. a human who follows today's walkthrough hits a `BadRequestError` on a
command that has worked for months.

## .the gap, precisely

two briefs carry the `account=demo` apply and neither sources the env:

| brief | what it says today |
|---|---|
| `howto.reapply-demo-oidc-role` | `use.ehmpathy.demo --owner admin`, then plan + apply — no `source` |
| `howto.add-test-permissions` | same shape, for the root half; its demo note is likewise silent |

the step they will need:

```sh
cp -n provision/aws.auth/account=demo/.env.example provision/aws.auth/account=demo/.env
# fill the two values from the collaborator's PRIVATE tree, then:
source provision/aws.auth/account=demo/.env
```

| var | holds |
|---|---|
| `GROVE_REACH_CAMP_ACCOUNT_ID` | the camp account id, 12 digits |
| `GROVE_REACH_CAMP_ROLE_NAME` | the camp grove role our trust policy names as principal |

⚠️ **the failure mode past that is worse than a throw.** per that branch's own `.env.example`: a
*wrong* value is a **permanently dead reach that both halves apply cleanly into**. the resolved
principal arn in the plan diff is the sole catch for it — so the howtos owe a "read the principal
arn" line beside the `source` line, not merely the `source` line.

## .the shape of the fix

1. add the `cp` + `source` step to `howto.reapply-demo-oidc-role`, ahead of its plan command
2. add the same to the demo half of `howto.add-test-permissions`
3. add a "read the resolved principal arn in the plan" check to both — the dead-reach guard
4. note in both that the two values live in a **private** tree, so an agent cannot supply them

## .why it is not done in this round

it fails **SAFE**: the step does not exist on `main` yet. to document it now would describe a
requirement the current `account=demo/resources.ts` does not have, and send a human to a
`.env.example` that is absent from their tree.

⇒ the correct moment is **the merge of that branch**, and the edit belongs with it — not smuggled
into an unrelated s3 feature branch. no fulcrum is owed: no call was best-guessed, and the halt that
surfaced it is recorded at `blocker/5.1.execution.from_vision.md`, step 2.
