# 🌙 dream: model `NoncurrentVersionTransitions` on the s3 bucket lifecycle

**kind** feat · **owner** `ehmpathy/declastruct-aws` · **caught** 2026-09-10

## .the cue that fired

a dimensional decomposition of the s3 lifecycle, run at the `1.vision` stone of
`#99` while the wisher proposed a reshape (`F16`). the 2×2 of **{current, noncurrent} ×
{expire, transition}** has three cells covered and one empty:

| | expire | transition |
|---|---|---|
| **current version** | 🟢 `expireAfterDays` — shipped `1.11.0` | 🟢 `transitions` — shipped `1.11.0` |
| **noncurrent version** | 🟢 `expireNoncurrentVersionsAfterDays` — `#99` | 🔴 **empty** |

⇒ **the walk is what surfaced it.** under the flat `…AfterDays` names, four fields in a row read as
a complete set; under the decomposition, the hole is an absent key.

## .the gap, precisely

aws models the fourth cell and this package does not. verified in `@aws-sdk/client-s3`:

- `models_0.d.ts:6573` — `NoncurrentVersionTransitions?: NoncurrentVersionTransition[]` on
  `LifecycleRule`
- `models_0.d.ts:6698` — the `NoncurrentVersionTransition` shape: `NoncurrentDays`,
  `StorageClass`, `NewerNoncurrentVersions`

this package's `DeclaredAwsS3BucketLifecycle` carries `transitions` and `expireAfterDays` only
(`src/domain.objects/DeclaredAwsS3BucketLifecycle.ts:18-29`), and neither the read
(`getBucketLifecycle.ts`) nor the write (`putBucketLifecycle.ts`) touches the noncurrent
transition array.

⇒ **checkable in one read:** a bucket whose lifecycle already carries
`NoncurrentVersionTransitions` round-trips through this package with that array **dropped** —
`putBucketLifecycle` rewrites the whole rule, so the declared write silently deletes a real aws
config the reader never saw.

## 🔴 .why it is sharper than a feature gap

`putBucketLifecycle` writes the **whole** `LifecycleConfiguration`, so any aws-side field this
package does not model is **erased on the next apply** rather than merely unavailable. that makes
the absent cell a **data-loss hazard** for a bucket configured outside declastruct, not an absent
convenience.

⚠️ **the same hazard covers every other unmodeled `LifecycleRule` field** (`Filter`, `ID`,
`AbortIncompleteMultipartUpload` until `#99` lands). the noncurrent transition is the one the walk
surfaced; the class is wider, and a survey is part of the fix.

## .the shape of the fix

1. **survey** `LifecycleRule` in `models_0.d.ts` and list every field this package drops on write —
   the noncurrent transition is one member of that set
2. **model the cell**: `DeclaredAwsS3BucketLifecycleNoncurrentTransition` as a peer of the extant
   `DeclaredAwsS3BucketLifecycleTransition`, with `NewerNoncurrentVersions` nullable
3. **cast both ways** in `getBucketLifecycle` / `putBucketLifecycle`, symmetric with the current
   transitions
4. **decide the erasure policy** for whatever the survey finds that stays unmodeled — a fail-loud
   on an unrecognized field beats a silent overwrite (`rule.forbid.failhide`)

⇒ if `#99` takes `F16`'s reshape, the natural home is `lifecycle.versions.transitions`, symmetric
with `lifecycle.objects.transitions`. if it does not, the flat name is
`noncurrentVersionTransitions`.

## .why it is not done in this round

**SAFE: no. CLEAN: no.**

- **not safe** — it changes what `putBucketLifecycle` writes, which is the exact operation `#99`'s
  acceptance criteria grade. a change here perturbs a suite mid-route
- **not clean** — it needs a new nested dobj, both casts, registration, and acceptance coverage
  (`rule.require.dao-and-acceptance-per-declared-resource`), and the erasure survey is its own
  investigation
- **out of the wish's bounds** — `#99` names four properties and this is a fifth
  (`rule.prefer.bounded-scope`)
