# 🌙 dream: integration aws calls hang 600s under full parallel load

kind: fix (deflake) · owner: declastruct-aws maintainers · caught 2026-11-16

## .the cue that fired

the full local integration run (`rhx git.repo.test --what integration --mode apply`, 48 suites, 865s) read `262 passed, 7 failed, 20 skipped`. two hang-shaped failures:
- `ssmParameterSecure.journey.integration.test.ts` [case4] setup hook: `Exceeded timeout of 600000 ms for a hook` at its `useBeforeAll`. alone, the same file passes in 42s, 13/13
- `ec2LaunchTemplate.journey.integration.test.ts` [case8][t0]: `Exceeded timeout of 600000 ms for a test`, then green on `jest.retryTimes` retry 1

## .the gap, precisely

- an aws sdk call can wait out jest's 600s cap under full load, with no request deadline that fails it fast
- `jest.integration.env.ts` notes `requestTimeout`/`connectionTimeout` + adaptive retry; one of these paths evidently does not get them, or throttle backoff exceeds them
- a retry that turns a 600s hang green hides the flake; the run of record took 865s for 48 suites

## .the shape of the fix

- `rhx cicd.deflake init` on these two journeys
- find the call that hangs (log each sdk call's start/end under `--detectOpenHandles`), confirm the client it uses carries the request deadline
- clamp: under forced throttle, the call fails fast with a named error, never a 600s hook timeout

## .why it is not done in this round

neither file is touched by the grove trust fix, and each passes alone; a deflake route is its own scope (fulcrum F8).
