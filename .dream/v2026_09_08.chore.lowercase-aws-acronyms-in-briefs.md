# 🌙 dream: lowercase the aws acronyms across `.agent/` briefs and `provision/`

**kind** · chore  ·  **owner** · unclaimed  ·  **caught** · 2026-09-08

## .the cue that fired

a `role-standards-adherance` self-review on stone `5.1.execution.from_vision` checked the changed
files against `rule.forbid.shouts` (ehmpathy/mechanic — *"acronyms must be lowercase — no shouts …
capital acronyms = blocker"*).

the tell was not the rule. it was a **self-inconsistency inside one line I had authored**:

```
 * .what = the iam role every ahbode camp grove box wears via IMDS
```

`iam` lowercase and `IMDS` uppercase, in the same jsdoc line. the same shape appeared twice more:

- `readme.md` — *"makes the sdk skip your exported session entirely and fall through to IMDS"*
- `howto.revoke-grove-reach.md:124-126` — *"the aws sdk skips the env-var credential provider"*
  two lines above *"falls through to **IMDS**"*

⇒ **the divergence was invisible as a rule violation and obvious as an inconsistency.** a reader who
scans one line cannot tell which form the file means, so the file has no convention at all.

## .the gap, precisely

the repo writes aws-domain acronyms **both ways**, with no rule that parts them.

| population | measured 2026-09-08 |
|---|---|
| `.agent/repo=.this/role=any/briefs/*.md` | **175 occurrences across 31 files** of `IMDS\|SSO\|OIDC\|IAM\|STS\|AWS\|SDK\|EC2\|VPC\|SSM\|SCP` |
| the heaviest | `rule.require.vpc-test-cleanup-both-ends.md` (26) · `rule.forbid.dao-for-narrow-usecase-resource.md` (22) · `hazard.local-green-cicd-red.oidc-role-not-reapplied.md` (19) |
| `provision/aws.auth/account=demo/resources.oidc.ts` | 4 — among them `'Demo role for github actions (OIDC)'`, a live `description` value aws renders |

**checkable evidence** — the same file often carries both forms:

- `resources.oidc.ts:15` jsdoc reads *"github oidc resources for ci/cd access"* (lowercase)
- `resources.oidc.ts:46` reads `description: 'Demo role for github actions (OIDC)'` (uppercase)

⇒ one file, one acronym, two forms, 31 lines apart. **that pair is the whole case**, and it needs no
appeal to a rule to read as a defect.

## .the shape of the fix

1. **decide the bound first, and write it down.** three classes must NOT be swept, and a naive
   find-and-replace would break all three:
   - **literals a reader or a machine must type** — `AWS_PROFILE`, `AWS_REGION`,
     `AWS-StartSSHSession`, `AWS-RunShellScript`, `AWS::CloudWatch::Alarm`, url paths such as
     `docs.aws.amazon.com/IAM/latest/…`
   - **identifiers** — `DeclaredAwsIamRole`, `sdkSsm`, `getDeclastructAwsProvider`. `rule.forbid.shouts`
     already prescribes the camelcase treatment (*"treat acronyms as regular words"*), and these
     already conform
   - **live aws values** — `resources.oidc.ts:46`'s `description` is a string aws renders in the
     console. a change to it is a **plan diff and an apply**, never a prose edit. ⇒ file it
     separately, or leave it
2. **sweep prose only** — markdown bodies and `//` / jsdoc comments.
3. run it per-file with `sedreplace --mode plan` first; the plan output is what proves class 1 was
   not caught.
4. re-run `git.repo.test --what format|types|lint`.

⚠️ **a whole-word regex is not enough** — `\bIAM\b` matches the url path at `resources.oidc.ts:28`.
the bound has to be applied by a read of each hit, which is why this is a sweep rather than a
one-liner.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

| question | answer |
|---|---|
| **safe?** | ⚠️ mostly — but `resources.oidc.ts:46` is a live aws `description`, so one hit is a real apply |
| **clean?** | ⛔ **no.** 31 brief files plus the `provision/` tree are wholly outside this wish's diff, and the wish scopes to the demo-account grant |

⇒ **dirty, so it is deferred** — and a dirty deferral is a judgment, so it is also worth a fulcrum
row if this dream is ever picked up inside a route.

🔴 **and a partial sweep is worse than none.** `rule.forbid.domain-term-synonyms`'s no-mass-rewrite
clause and r4's own lesson both hold: *"a partial rename is worse than a consistent extant set."*
31 files half-converted leaves a reader unable to infer either convention.

## .what WAS fixed in this round, and why that much

scouts-honor bounds the fix to **on contact, in scope**. so the four files this stone authored or
heavily edited were made internally consistent — 14 occurrences:

| file | fixed |
|---|---|
| `provision/aws.auth/account=demo/resources.reach.ts` | `IMDS` → `imds` (1) |
| `provision/aws.auth/account=demo/resources.ts` | `OIDC`, `GitHub Actions` ×2, `CI/CD` (4) |
| `provision/aws.auth/account=demo/readme.md` | `OIDC`, `CI/CD`, `IMDS` ×2, `SSO` ×2, `CI-red` (7) |
| `.agent/repo=.this/role=any/briefs/howto.revoke-grove-reach.md` | `IMDS`, `SSO` (2) |

⇒ each of those four files now reads one way throughout. `resources.oidc.ts` was **left alone** — it
is not in this stone's diff, and its one live `description` value needs an apply rather than an edit.
