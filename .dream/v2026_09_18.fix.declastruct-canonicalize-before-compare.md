## .the gap, precisely

`declastruct` · `src/domain.operations/plan/computeChange.ts`:

```ts
const checkAreResourcesEquivalent = (input: {
  remote: DomainEntity<any>;
  desired: DomainEntity<any>;
}): boolean => {
  const remoteSerialized = serialize(omitReadonly(input.remote));
  const desiredSerialized = serialize(omitReadonly(input.desired));
  return remoteSerialized === desiredSerialized;
};
```

`serialize` defaults to `{ lossless: false, orderless: false }`. so the compare is **shape- and
order-sensitive**, and two documents a provider considers identical serialize differently:

| the provider says identical | `serialize` says | consequence |
|---|---|---|
| `['a','b']` ≡ `['b','a']` | ❌ different | every plan reads `UPDATE` |
| `'x'` ≡ `['x']` | ❌ different | every plan reads `UPDATE` |

⇒ **a permadiff: an `UPDATE` row, forever, on a resource nobody edited.** the cost is more than
noise — a runbook whose fail-safe is *"a human STOPS on an unexpected plan row"* trains that human
to skim past one.

🔴 **and it is not iam-specific.** any api that accepts a `T | T[]` union or returns a set in
unstable order hits it — s3 tag sets, sns subscription lists, security-group rules, and whatever
the stripe and unix providers touch.

## .why it cannot be fixed in a provider

🔴 **empirically falsified, not merely reasoned.** a fold of one-element arrays in
`declastruct-aws`'s read cast was tried: full run **1302 passed, 1 failed**, and the failure was a
document that legitimately declared four lists of one. the fold **created** the permadiff it looked
like it prevented.

⇒ the reason is structural: **a cast holds one side.** any canonicalization it performs is
asymmetric, so it rescues one legal declaration shape and breaks the other. the desired side is
built by a consumer via `new`, which no provider library reaches.

**the compare is the one place both sides are in hand.**

## .the shape of the fix

```ts
/**
 * .what = one canonical form per value, for EQUALITY only
 * .why = a provider api may return a shape it was not given. this collapses the
 *   distinctions no provider considers meaningful, identically on both sides
 */
const canonicalize = (value: unknown): unknown => {
  if (Array.isArray(value))
    return value.length === 1
      ? canonicalize(value[0])
      : value.map(canonicalize);
  return value;
};

const checkAreResourcesEquivalent = (input: {
  remote: DomainEntity<any>;
  desired: DomainEntity<any>;
}): boolean =>
  serialize(canonicalize(omitReadonly(input.remote)), { orderless: true }) ===
  serialize(canonicalize(omitReadonly(input.desired)), { orderless: true });
```

two arms:

| arm | closes | cost |
|---|---|---|
| **sort** — pass `{ orderless: true }` | array order | ✅ **zero.** `domain-objects` already ships the flag; the planner does not pass it |
| **fold** — a one-element array to its bare value | `'x'` vs `['x']` | the nine-line helper above |

🔴 **both are SYMMETRIC** — applied identically to each side, for equality only. they change no
written document, no serialized plan state, and no `getDisplayableDiff` output. so a caller cannot
break: the change can only turn an `UPDATE` into a `KEEP`, never the reverse.

## .the one call that needs a human

🔴 **the sort arm asserts array order is never semantic in a declared resource.** that holds for
every case known here, and it is a claim over every provider rather than one:

- `resource: ['arn-a','arn-b']` — a set. order is noise
- a route table's `routes`, an s3 lifecycle rule list, an sns filter — **unwalked**

⇒ if any resource does carry ordered semantics, ship the **fold** arm alone — it retains order —
and gate the sort behind a per-resource opt-in. **the fold arm closes the reported defect on its
own.**
